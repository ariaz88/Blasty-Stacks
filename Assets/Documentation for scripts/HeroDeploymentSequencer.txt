The old one-load-per-MATCH serial queue (6s x matches, back to back) is GONE.
Arash's brief: which match a hero came from no longer matters. At BATTLE, count the
earned heroes per TYPE; every type gets its own timer; ALL timers start on the same
frame; each fill releases ONE hero of that type; stronger types load slower
(5.5 / 7 / 8 / 9s for the four deployed heroes, ordered by base CP); a type that runs
out greys out; the level ending stops everything.

PURPOSE
-------
Releases the heroes earned in the puzzle onto the battlefield, one TYPE per timer,
all timers in parallel.

  Example: Valkyrie x3 @5.5s, Minotaur x2 @7s
    Valkyries at 5.5, 11, 16.5   Minotaurs at 7, 14
  The first hero of a type comes out after ONE full load, never at 0s.

It owns no roster and spawns nothing itself: counts come from
PlayerWaveManager.EarnedHeroes; spawning is PlayerWaveManager.DeployOne.

NESTED CLASS  Track  (one per hero type)
----------------------------------------
  Def        UnitDefinitionSO of the type          UnitId  Def.unitId
  Total      how many were earned ("/total")        Remaining  not released yet
  Interval   seconds per load (ResolveDeployInterval)
  Elapsed    seconds into the current load
  Progress   Elapsed/Interval, 0..1; 0 once Remaining == 0
  Setters are `internal` - only this class writes them.

INSPECTOR FIELDS
----------------
  awardWaitTimeout (float, min .5, default 5)  safety net for the award wait.
  Refs (left empty = found in the scene at Awake)
    waveManager  (PlayerWaveManager)      counts + spawning. Missing = error.
    battleStart  (BattleStartController)  the trigger.

PUBLIC API
----------
  Tracks             IReadOnlyList<Track>; NULL until built (BATTLE not pressed or
                     still waiting on awards); EMPTY = battle with no heroes.
  Running            true while the timers tick.
  HeroesStillComing  true while any hero has yet to reach the field: still waiting
                     on awards, a track has Remaining > 0, or a released hero is
                     queued for a free stage (PlayerWaveManager.HeroesWaitingForGate).
                     False after StopDeployment. Read by LevelGameManager.
  StopDeployment()   stops every track where it stands, clears PlayerWaveManager's
                     gate queue. Permanent for this level.
  event HeroReleased(Track)  one hero handed to PlayerWaveManager.
  event AllDeployed()        every track ran out (NOT raised by StopDeployment).

FLOW
----
  OnEnable   subscribes BattleStartController.OnBattleStarted and the STATIC
             LevelGameManager.OnGameStateChanged (unsubscribed in OnDisable).
  HandleBattleStarted -> BuildTracksWhenAwarded() [coroutine]
      1. Waits until MatchesReleased >= MatchesCleared (or DeploymentFailed, or
         awardWaitTimeout). See the 2026-09-16 race below.
      2. BuildTracks(): counts EarnedHeroes per def, Interval from
         waveManager.ResolveDeployInterval(def), sorts by units-database order,
         sets tracksReady, logs one line per type.
      3. Running = tracks.Count > 0 (no tracks -> AllDeployed at once).
  Update     (only while Running) adds the SAME deltaTime to every track with
             Remaining > 0. On Elapsed >= Interval: Elapsed -= Interval (overshoot
             carried so the rhythm stays exact), Remaining--, DeployOne(def),
             HeroReleased. When no track has any left: Running=false, AllDeployed.
  HandleGameStateChanged(state != Playing) -> StopDeployment().

HOW IT CONNECTS
---------------
  - BattleStartController.OnBattleStarted -> builds and starts the tracks.
  - PlayerWaveManager.EarnedHeroes        -> the per-type totals.
  - PlayerWaveManager.ResolveDeployInterval -> UnitDefinitionSO.deployInterval, or
    the level's StageDeploymentPlanSO.deployIntervals override.
  - PlayerWaveManager.DeployOne(def)      -> spawns on a FREE, reserved stage (waits
    if none), poses, jumps to the rear lane.
  - LevelGameManager.OnGameStateChanged   -> win/loss stops deployment.
  - LevelGameManager.IsMutualWipe         -> reads HeroesStillComing.
  - HeroStatsPanel POLLS Tracks every frame and draws each card.

NOTES / RISKS
-------------
  - Update + one shared deltaTime rather than a coroutine per type: tracks cannot
    drift apart, and GameplayPause (timeScale 0) freezes them together. Scaled
    time on purpose - a paused game pauses deployment.
  - At most ONE release per track per frame; a frame longer than an Interval just
    releases the next one a frame later (Elapsed carries).
  - Tracks are built once per level. After a revive (currently disabled) they are
    not rebuilt - StopDeployment already ran on ReviveOffer.
  - 2026-09-16 RACE (kept): SealForBattle does not flush PlannedWaveLoop, which
    awards a match only after nextWaveDelay (0.75s). Counting immediately once
    produced ZERO heroes (stage 1, gate 500 -> 458). Hence the award wait.
  - Before 2026-09-27 nothing ever called StopQueue, so on a WIN (the game is not
    paused on win) the queue kept releasing heroes under the win panel. Fixed by
    the OnGameStateChanged subscription.

================================================================================
  TutorialTooltip.cs
  Path : Assets/Scripts/Tutorial/TutorialTooltip.cs
  Type : MonoBehaviour (+ enum TutorialTooltipSide)
  Layer: Tutorial
  Scenes: lives on the TutorialOverlay prefab instance (built at runtime when the
          prefab does not carry one)
================================================================================

PURPOSE
-------
A speech bubble that FOLLOWS a target, as opposed to TutorialCaption, which is
one fixed line under the board.

Both live on the overlay and neither knows about the other: a board lesson goes
on using the caption, a guided chain uses this, and TutorialOverlay.ClearAll
hides both. Keeping them separate is why adding this needed no change at all to
the board tutorial.

TutorialTooltipSide: Auto = 0, Above = 1, Below = 2.

INSPECTOR FIELDS
----------------
  bubble / label / tail / group     parts; built at runtime when empty
  bubbleSprite  (Sprite) optional 9-sliced rounded rect. Empty = sharp rectangle
  tailSprite    (Sprite) optional triangle. Empty = a small square
  bubbleColor / textColor / font / fontSize
  maxWidth      (float) 760   wrap width before padding
  padding       (Vector2) 46 x 30
  gap           (float) 28    target edge -> tip of the tail
  edgeMargin    (float) 40    closest the bubble may come to the canvas edge
  tailSize      (Vector2) 34 x 20
  fadeTime      (float) 0.22  unscaled

PUBLIC API
----------
  Configure(Canvas)                                  called by TutorialOverlay
  Show(text, Func<Rect?> targetScreenRect, side)
  Hide()

FLOW
----
  Show        resize the bubble to the text, store the provider, fade in
  LateUpdate  fade toward the target alpha; while visible, re-ask the provider
              and reposition
  Reposition  pick the side, clamp the bubble inside the canvas, then slide the
              tail along the bubble edge so it still points at the target

HOW IT CONNECTS
---------------
  - TutorialOverlay exposes it as .Tooltip and clears it in ClearAll.
  - TutorialRunner.ShowTooltip / HideTooltip wrap it.
  - TutorialFocusTapStep passes the SAME Func<Rect?> to the tooltip and to
    TutorialFocusGate, so the hole and the bubble can never disagree about where
    the target is.

NOTES
-----
  - Auto side picks BELOW when the target sits high on screen and ABOVE
    otherwise, so the bubble never leaves the screen.
  - The horizontal clamp is why the tail is positioned separately: the Units nav
    button sits in the bottom-left corner, so the bubble gets pushed inward and
    a centred tail would no longer be over the button.
  - Sizing uses label.GetPreferredValues then sets sizeDelta explicitly, rather
    than a ContentSizeFitter - deterministic, and no layout-rebuild timing
    surprises at timeScale 0.
  - Fades are a manual unscaled loop copying TutorialCaption, NOT DOTween, which
    would freeze at timeScale 0 unless every tween got SetUpdate(true).
  - A null result from the provider fades the bubble out rather than leaving it
    stranded over an element that has gone away.

2026-09-23 FIX — NEVER USE ?? WITH A UnityEngine.Object
--------------------------------------------------------
Reported three times as "the 'Go back' tooltip stays on screen after I press
Back". Live inspection showed the cause immediately:

    tooltip go='Tooltip' activeInHierarchy=True  cg=NULL  alpha=-1

There was NO CanvasGroup on the Tooltip object at all, because EnsureParts did:

    group = gameObject.GetComponent<CanvasGroup>() ?? gameObject.AddComponent<CanvasGroup>();

`??` uses plain reference equality and BYPASSES UnityEngine.Object's overloaded
==, so Unity's "fake null" was accepted as a real component and AddComponent was
never called. Every later `if (group)` — which DOES use the overload — then
evaluated false, so the fade in LateUpdate never ran, and because
SetPartsActive(false) lived INSIDE the fade branch the bubble was never switched
off. It stayed on screen, fully opaque, for the rest of the session.

Two changes:
  1. EnsureParts now does an explicit two-step null check instead of `??`.
  2. SetPartsActive(false) moved OUT of the fade branch, and LateUpdate has an
     else-branch that honours Hide() even with no CanvasGroup at all. Hiding must
     not depend on the fade succeeding.

RULE: in this codebase, never write `??`, `?.` or `??=` against a
UnityEngine.Object. Use `if (!x)`, which respects the overloaded operator.

VERIFIED end to end by driving all four steps through ExecuteEvents in a live
session: after the Back click, tooltip alpha 0, Bubble and Tail inactive, runner
stopped, gate released, all four scrim plates inactive, and the tutorial flag
written.

2026-10-05 — GEM-HOLDER ART REPLACES THE PLACEHOLDER BUBBLE
-----------------------------------------------------------
Arash: every tooltip of the stage-6 onboarding must use the
Gameplay_Gem-holder_H3P asset (Arts/.../New GamePlay Assets), and stretching it
sideways must NOT stretch its bottom tail - only the body grows.

  The placeholder: TutorialOverlay built this component at runtime with no
  sprites, so the bubble was a plain white rectangle + a small square tail.
  TutorialOverlay.prefab now carries a saved "Tooltip" child (sibling 3, under
  the Hand; the runtime-built FocusGate/FocusFx are inserted first so the scrim
  stays below it) with the holder sprites assigned - GetComponentInChildren picks
  it up, nothing is built.

  The texture (73 x 121, UNCHANGED) is now sliced into extra sprites:
      Gameplay_Gem-holder_H3P_0   full image, ORIGINAL internalID kept - used
                                  by LevelTemplate "New Stage UnLock Holder/Image".
                                  !! Never drop it when re-slicing.
      Holder_LeftCap         x 0-13     border (L,B,R,T) = (0,33,0,15)
      Holder_Strip           x 14 (1px) same border - the plain body column
      Holder_CenterWithTail  x 15-57    same border - holds the tail AND the
                                        gap in the bottom outline where the
                                        tail joins (cols 18-41, rows 100-103)
      Holder_RightCap        x 59-72    same border
  Rows 15-87 are the only identical rows (top border 15, bottom 33 = rows
  88-120 incl. the tail). Column 14 == column 58, so one strip sprite serves
  both sides. A plain body + tail split would NOT work: the outline gap at the
  junction would widen with the body.

  New fields: holderLeftCap / holderStrip / holderCenter / holderRightCap,
  holderScale 3 (canvas units per art px; Image.pixelsPerUnitMultiplier =
  1/holderScale), holderTailPx 17 (rows 104-120), holderTextColor white (the
  fill is navy 56,67,87 @ 75%). Prefab padding 60 x 46.
  UsesHolder = all four sprites set; then bubbleSprite / tailSprite / the
  separate Tail object are ignored (tail kept inactive).

  Layout (LayoutHolder, every Reposition):
      [left cap][strip ....][centre+tail][.... strip][right cap]
  caps and centre at fixed width, the two strips take the rest. The centre
  slides by (targetX - bubbleX), clamped so both strips stay >= 0 - the tail
  keeps pointing at the target after the edge clamp moves the bubble. Each
  piece spans the bubble's top to the tail tip below its bottom (HolderTailH),
  sliced so only rows 15-87 stretch vertically. Below its target the
  "HolderArt" root is flipped (scale y -1 about the bubble centre) so the tail
  points UP; the label is not a child of it and stays upright. Gap maths in
  Reposition uses HolderTailH instead of tailSize.y.
  ResizeBubble clamps to min width caps+centre+2 strip px and min height = the
  body's top + bottom borders.

  PreviewLayout(text, tailOffset, above): EDITOR ONLY, for edit-mode captures.
  Verified in edit mode (short / long+offset tail / below-flipped); NOT seen in
  a live tutorial run yet.

  BoardInputController.cs

PURPOSE
-------
The PRIMARY input handler for the puzzle board. It picks up a piece under the
pointer, drags it FREELY around the board, refuses illegal positions, snaps it
onto the grid on release, and then asks MatchResolver to check for a match.
This is the script the player interacts with on every turn.

REWRITTEN 2026-08-25. The old version parked the piece on a cell centre and
SmoothDamp'ed toward it, so the piece only moved when the pointer crossed a cell
boundary - it read as chunky, cell-by-cell sliding, worst on diagonals. The
piece now lives at a CONTINUOUS position; the grid is only consulted for
legality and for the single snap on release.

INSPECTOR FIELDS
----------------
  Refs
    board            (BoardGridXY)
    cam              (Camera)  defaults to Camera.main
    moveBudget       (PuzzleMoveBudget, optional) the per-level move cap. Left
                     empty it is resolved with FindObjectOfType in Awake. NO
                     PuzzleMoveBudget in the scene = unlimited moves, which is
                     what keeps the older stages unchanged.
  Picking Layers
    pieceLayer3D     (LayerMask, default Everything) legacy 3D collider support
    pieceLayer2D     (LayerMask, default Everything) SET THIS to your Pieces
                     layer - leaving it as Everything makes picking slower and
                     can grab unintended colliders.
  Visuals
    liftWhileDragging (float, default 0.10) lift along the board normal. Scenes
                     currently author -0.5, i.e. toward the camera.
  Drag Feel
    maxSubStepCells  (float 0.05-0.5, default 0.25) largest movement resolved in
                     one collision sub-step, in CELLS. MUST stay <= 0.5 or a
                     fast flick can tunnel straight through an occupied cell,
                     because a sub-step longer than one cell can skip a whole
                     integer bracket without ever testing it.
    maxSubStepsPerFrame (int, default 64) safety cap so a huge pointer jump
                     cannot stall a frame. On an 8x6 board the real worst case
                     is ~32 sub-steps, so the cap never binds in practice.
    settleDuration   (float 0-0.3, default 0.07) seconds spent easing onto the
                     exact cell centre after release. 0 = snap instantly (old
                     behaviour). Because the drag is 1:1 the piece can be up to
                     half a cell off centre at release, which pops visibly
                     without this ease.
    restExactlyWhereReleased
                     (bool, default OFF) NO-SNAP MODE. ON: the piece does not move
                     at all on release - it stays exactly where the finger left it
                     and books the one cell each block mostly covers. OFF: it eases
                     onto the nearest cell over settleDuration. See NO-SNAP below.
                     ON in LevelTemplate.prefab (every stage) and Tutorial_Board_01.
                     THE USER DOES NOT WANT ANY RELEASE SNAP IN THIS MODE (2026-09-26).
  REMOVED 2026-09-26: releaseSnapCells (near-cell release snap). It lived one day;
                     the user rejected snapping outright and it did not fix the
                     gap for drops > 0.25 from a line. Solved by BODY COLLISION below.
    gapAssistCells   (float 0-0.49, default 0.15) how far, in cells, the piece may
                     be pulled onto the nearest LANE on the perpendicular axis
                     (a whole cell line OR a line flush with an obstacle edge)
                     when the axis it is being pushed along is walled.
                     KEEP THIS SMALL - it displaces the piece WITHOUT moving the
                     finger, so a large value is felt directly as "I released it
                     here and it landed there". It was 0.4 and that was a large
                     part of that complaint. Only a safety net for the
                     zero-clearance corridor case. 0 = off. See GAP ASSIST below.
  REMOVED: smoothTime and maxSpeed. The drag is now 1:1 with the pointer, so
  there is nothing left to damp. Scenes still carry the old YAML lines; Unity
  ignores serialized fields that no longer exist, so nothing breaks.

RUNTIME STATE
-------------
  activePiece      the piece currently held
  freeAnchor       (Vector2) THE CONTINUOUS ANCHOR, in cell units. This is the
                   heart of the rewrite. freeAnchor == (3, 4) means the piece
                   sits exactly on cell (3,4); (3.4, 4.0) means it straddles
                   cells 3 and 4 on X. Everything the player sees is drawn from
                   this value.
  lastValidAnchor  Vector2Int.RoundToInt(freeAnchor) - the cell the piece will
                   commit to if released now. Always legal, see NOTES.
  dragStartAnchor  the anchor the piece sat on when it was picked up. EndDrag
                   compares it against lastValidAnchor to tell a real move from
                   a tap - this is the whole definition of "a move".
  grabOffsetLocal  (Vector2) pieceLocal - pointerLocal at pickup, in BOARD-LOCAL
                   units (not cells). This is what makes dragging feel correct:
                   the piece keeps the exact sub-cell point under the finger
                   instead of jumping its origin to the pointer. Replaces the
                   old whole-cell `grabbedOffset`, which could only preserve the
                   grabbed cell, not the grabbed point.
  boardLocalZ      board plane depth in the board's own local space, cached at
                   pickup so AnchorToWorld does not have to re-derive it.
  dragStartFree    (Vector2) continuous position at pickup; where a no-snap
                   release slides back to if the board refuses the booking.
  obstacleBoxes    (List<Vector2>) COLLISION SNAPSHOT taken at pickup: min corner
                   of every 1x1 box the held piece may not overlap - each block
                   of every other placed piece where its TRANSFORM really is,
                   plus blocked/ghost cells. See BODY COLLISION below.
  anchorMin / anchorMax
                   anchor range that keeps every block of the held shape on the
                   board (board edges are handled as a clamp, not as boxes).
  settlePiece / settleFrom / settleTo / settleT
                   the release ease. Driven from Update, not a coroutine, so it
                   can be force-completed at any moment (see CompleteSettle).
  tmpFootprint / tmpLanes   reused lists

INPUT ROUTING
-------------
  Update() first ticks the release settle, then selects the input path:
      UNITY_EDITOR || UNITY_STANDALONE  ->  MouseUpdate()
      otherwise (mobile)                ->  TouchUpdate()
  MouseUpdate  maps GetMouseButtonDown/GetMouseButton/GetMouseButtonUp.
  TouchUpdate  maps touch 0 Began / Moved+Stationary / Ended+Canceled.
  Both funnel into TryBeginDrag, TryDrag and EndDrag.
  Note that on the mouse path, Down and Held are BOTH true on the pickup frame,
  so TryDrag runs immediately after TryBeginDrag. That is harmless: the grab
  offset makes the first frame's desired anchor equal the current one.

BOARD SPACE HELPERS
-------------------
  BoardLocalZ()
      The board plane's depth in board-local space, read back through
      CellCenterWorld(0,0). BoardGridXY keeps its `localZ` private, so this is
      how the controller learns it without widening that API.

  PointerToBoardWorld(screenPos)
      Intersects the pointer ray with the board plane
      (Plane(BoardPlaneNormal(), CellCenterWorld(0,0))). Correct for both
      orthographic and perspective cameras and for a rotated board. Falls back
      to the old flat ScreenToWorldPoint projection only if the ray is parallel
      to the plane. Both picking and drag maths go through this, so the grab
      offset can never disagree with the drag position.

  LocalToAnchor(local) / AnchorToWorld(anchor)
      Continuous anchor <-> position, using board.CellPitch (cellSize +
      cellPadding) and a half-cell offset, mirroring CellCenterLocal in
      BoardGridXY. THIS IS THE BUG FIX for the old drift: the previous code
      divided by CellSize, so with cellPadding 0.055 on a 1.086 cell the piece
      fell ~5% behind the finger per cell crossed - nearly half a cell across
      the board.

LEGALITY
--------
  IsAnchorLegal(anchor, piece)
      Builds the footprint and calls AreCellsPlaceableForMover with the piece's
      own id, so its current cells never block itself. Note the piece stays
      registered on its ORIGINAL cells for the whole drag - TryPlace only runs
      on release - which is exactly why passing its own id matters.

  BODY COLLISION (rewritten 2026-09-26) - BuildCollisionSnapshot / IsFreeAnchorLegal / ResolveAxis
      THE BUG IT FIXES ("Piece Movement Bug" video, Assets/Arts/Reference videos/Board):
      collision used to test the cells other pieces had BOOKED. A piece resting at
      x = 2.85 booked cells 2 AND 3, so a same-colour piece pushed toward it could
      not enter cell 3 and stopped with a visible gap (0.15-0.85 cell). The match
      test needs <= touchTolerance (0.05), so they never matched, and the pushed
      piece just shook in place (pickup highlight) without moving.
      NOW: collision is against the other pieces' REAL bodies. At pickup,
      BuildCollisionSnapshot reads every other placed piece's transform through
      BoardGridXY.WorldToContinuousAnchor (SnapNearWhole'd) and records each block
      as a 1x1 box; blocked/ghost cells are added as boxes too. Nothing else moves
      while a piece is held, so one snapshot per drag is exact.
      IsFreeAnchorLegal(anchor): inside [anchorMin, anchorMax] and no block of the
      piece overlaps any obstacle box (|dx| < 1 AND |dy| < 1, epsilon 1e-4).
      Distance exactly 1 is legal - that is flush contact.
      No snapping is involved anywhere. Verified by MCP fuzz (400 random drags):
      0 body overlaps, 0 double bookings, 0 out-of-bounds, 0 missed matches.

PICKING
-------
  TryPickPiece(screenPos, out piece)
      Prefers a 2D pick: PointerToBoardWorld + Physics2D.OverlapPoint, then
      walks up with GetComponentInParent<PieceSimple>.
      Falls back to a 3D Physics.Raycast for any legacy prefabs that still have
      3D colliders.

  TryBeginDrag(screenPos)
      1. CompleteSettle() first, so a piece still easing onto its cell is landed
         and match-resolved before the board is touched again. Without this a
         fast second tap would read stale occupancy.
      2. Refuses the pickup entirely when moveBudget exists and HasMovesLeft is
         false - that is how "the board stops being interactable after n moves"
         is enforced. A drag already in flight is unaffected, because only new
         pickups pass through here.
      3. Resolves the anchor from piece.Anchor, which PieceSimple.TryPlace keeps
         authoritative. Only if that is somehow illegal does it fall back to
         TryWorldToCell and then to a clamped rounded read of the transform.
         The old code went straight to TryWorldToCell and, on failure, clamped
         Vector2Int.zero - which teleported the piece to the bottom-left corner.
      4. BuildCollisionSnapshot(piece), then seeds freeAnchor from the piece's
         ACTUAL transform (falls back to the whole anchor only if that reads as
         illegal), records dragStartFree and grabOffsetLocal, and applies ONLY the
         lift. There is no snap to the cell centre on pickup.

DRAGGING  (the interesting part)
--------------------------------
  TryDrag(screenPos)
      1. desired = LocalToAnchor(pointerLocal + grabOffsetLocal) - a FLOAT
         anchor, not a cell.
      2. Axis constraints (AllowsX / AllowsY) pin the locked component to
         dragStartAnchor, continuously.
      3. MoveFreeAnchorTowards(desired).
      4. lastValidAnchor = RoundToInt(freeAnchor).
      5. Writes the transform straight from freeAnchor plus the lift. No
         damping, no snapping - the piece is exactly where the finger is, minus
         whatever the collision clamps took away.

  MoveFreeAnchorTowards(desired)
      Splits the frame's delta into sub-steps of at most maxSubStepCells and
      walks them. Per sub-step:
        - fast path: if the full diagonal is legal, take it. This is what makes
          an unobstructed diagonal drag a straight line instead of a staircase.
        - otherwise resolve X and Y INDEPENDENTLY via ResolveAxisAssisted, in
          order of which axis the player is pushing hardest. If X is walled the
          Y component still moves, so the piece glides along the wall rather
          than snagging. THIS is the fix for the old code, which consumed the
          entire X delta before even looking at Y and therefore traced an
          L-shaped path through the grid.
        - if neither axis moved, the piece is wedged; break out for this frame.
      Finally snaps near-whole components (see SnapNearWhole) so a corridor stays
      float-exact instead of drifting by rounding dust.

  GAP ASSIST - ResolveAxisAssisted(axis, target) / CollectLanes
      Resolves one axis, and IF that axis is completely walled, retries after
      pulling the OTHER axis onto a nearby LANE (at most gapAssistCells away,
      never an axis the piece has locked). Lanes = the nearest whole cell line
      plus every position flush with an obstacle edge (obstacle +/- 1 - offset),
      tried nearest first - once pieces rest between cells, a corridor between
      two of them need not sit on a whole line. This is a drag-time assist only;
      nothing moves on release.
      WHY THIS EXISTS: with a genuinely free 1:1 drag, a corridor exactly as tall
      as the piece demands that the player hold the perpendicular axis at a
      float-exact whole number. That is impossible by hand, so the piece jams at
      the mouth of the gap while the pointer sails on - which is precisely the
      "it gets stuck and the mouse runs ahead" bug. The assist snaps the piece
      into the lane the moment it tries to enter and it then glides through.
      The pulled axis is LANE-LOCKED (laneLockedAxis) for the rest of the frame,
      otherwise the perpendicular resolve later in the same frame drags the piece
      straight back off the line it was just helped onto and the two fight
      sub-step by sub-step - visible as jitter.

  NO-SNAP RELEASE - restExactlyWhereReleased / TryRestInPlace
      When the toggle is ON, the piece's X/Y stay exactly where the finger left
      them; only the drag lift eases off (through the normal settle, so match
      resolution runs in CompleteSettle on landing, same as snap mode).
      BOOKING (changed 2026-09-26): each block books the ONE cell it mostly covers
      - the footprint of RoundAnchor(freeAnchor) - via PieceSimple.TryPlaceExact(...,
      snapRootToAnchor: false). The old rule booked EVERY overlapped cell (2 per
      axis for an off-grid piece); that was only needed because collision read the
      bookings. Collision now reads real bodies, so bookings are only a coarse map
      for match candidates, tutorial hints and "is the board empty".
      Why bookings cannot clash: bodies that do not overlap are >= 1 apart on some
      axis, and round(x + 1) == round(x) + 1, so they round to different cells.
      If float noise on an exact x.5 ever makes TryPlaceExact refuse, the piece
      slides back to dragStartFree (its old booking was never released). No snap.
      TryBeginDrag seeds freeAnchor from the ACTUAL transform, so touching an
      off-grid piece never teleports it onto a cell.

  REJECTED AND REMOVED: detent magnetism.
      An attempt to kill the release snap by bending the requested position toward
      whole cells (a power curve, flat near a cell and steep at the boundary) so the
      piece would already be on a cell at release.
      IT WAS WRONG AND WAS REMOVED THE SAME DAY. Bending the position toward cells
      IS cell-to-cell movement: the piece visibly lingers on a cell and then jumps
      the boundary - precisely the stepped, robotic feel this whole rewrite exists to
      eliminate. The requirement is a finger moving freely through space, and ANY
      position-bending scheme (lerp-to-centre, SmoothStep, power detents) contradicts
      it. DO NOT RE-INTRODUCE IT IN ANY FORM.

  REMOVED: ClampPointerOvershoot. It used to bleed slack out of grabOffsetLocal
      when a piece was walled, so the pointer could not run away from a stuck
      piece. But it MUTATED THE GRAB OFFSET, and cumulatively across separate
      blocking events - so the piece progressively slid out from under the finger,
      and the release then landed on the cell under the PIECE, not under the
      finger. That was a major part of "it snapped somewhere else".
      grabOffsetLocal is now fixed for the whole drag: the piece is rigidly
      attached to the grab point. A piece pushed into a wall separates from the
      finger and re-attaches exactly when the finger comes back, which is
      physically honest. The symptom it was papering over ("the mouse runs ahead
      and the stack is dead") was really the corridor jam, which the gap assist
      and magnetism fix properly.

  ResolveAxis(anchor, axis, target)
      A SWEEP: moves one axis toward target and stops EXACTLY flush against the
      first obstacle box ahead, wherever its edge is (on a cell line or between
      two). Only boxes overlapping the piece on the perpendicular axis count, so a
      piece exactly level with the row above slides past it. Clamped to
      anchorMin/anchorMax. Never moves the piece backwards (stays put instead).
      (Before 2026-09-26 it assumed every blocking edge was a whole cell and used
      Ceil/Floor - false once pieces rest between cells.)

RELEASE
-------
  EndDrag()
      Commits with TryPlace(lastValidAnchor) - which updates occupancy and
      jumps the root to the cell centre.
      ON FAILURE it falls back to dragStartAnchor, NEVER to p.Anchor.
      PieceSimple._anchor can hold a value that was never validated or occupied,
      because AutoBuildOffsetsFromChildren assigns it directly (bypassing
      TryPlace) and BoardBootstrapper calls that unconditionally - the `if` its
      own comment describes is missing. Trusting it could fling the piece to the
      far side of the board. dragStartAnchor is always a position the piece
      legitimately held.
      Then COUNTS THE MOVE, but only when lastValidAnchor != dragStartAnchor.
      That single comparison is the whole rule: a tap-and-release, and a drag
      the board refused (the anchor never advanced past the start), both leave
      the anchor unchanged and are therefore free.
      Finally it arms the settle: the piece is put BACK where the finger left it
      (lift included) and eased onto the centre over settleDuration.

  TickSettle() / CompleteSettle()
      TickSettle runs from Update and SmoothStep-lerps toward the centre.
      CompleteSettle finishes immediately - exact centre, then find a
      MatchResolver (on this object first, else in the scene) and call
      ResolveFrom(piece), which is what can trigger a blast and therefore a
      warrior wave. It is called from TickSettle when the ease finishes, from
      TryBeginDrag before a new pickup, and directly from EndDrag when
      settleDuration is 0.
      IMPORTANT: match resolution now happens at the END of the settle, roughly
      70 ms after the pointer is released, not on the release frame itself.

THE RELEASE SNAP  (understood and ACCEPTED, not a bug)
-----------------------------------------------------
  With a true 1:1 drag the piece can sit up to HALF A CELL from any cell centre
  when the player lets go, and it must land on a whole cell - so it always has
  somewhere to travel. Nothing picks the "wrong" cell: lastValidAnchor is always
  the nearest LEGAL one. You cannot have both "the piece is exactly under my
  finger" and "the piece is always exactly on a cell".

  A landing-preview ghost was built on 2026-08-25 to announce the landing in
  advance, and REMOVED the same day at the user's request - it looked bad in the
  scene. If this is revisited, the options considered were: a landing preview,
  light magnetism toward the nearest legal cell while dragging (shrinks the snap
  distance at the cost of a faint tug), both, or simply a longer settleDuration
  so the travel reads as motion rather than a teleport. The cheapest experiment
  is raising settleDuration - it needs no new code.

  IF A PREVIEW IS REBUILT: do NOT Instantiate the piece to make the ghost.
  Cloning it brings PieceSimple along, whose Start claims a second pieceId and
  occupies cells on the real board. Build it from generated quads instead.

HOW IT CONNECTS
---------------
  - Reads and moves PieceSimple; validates through BoardGridXY.
  - Calls MatchResolver.ResolveFrom on release -> may fire MatchResolver.OnBlast
    -> PlayerWaveManager spawns units. This is the start of the whole game loop.
  - Calls PuzzleMoveBudget.RegisterMove on every counted move, and reads its
    HasMovesLeft to gate new pickups.

NOTES
-----
  - INVARIANT: freeAnchor is only ever assigned a value that IsFreeAnchorLegal
    accepted (or a ResolveAxis sweep result, flush by construction). In snap
    mode every other piece sits on whole cells, so RoundAnchor(freeAnchor) is a
    legal cell and TryPlace on release cannot realistically fail.
  - Picking falls back to the 3D raycast in the stage scenes (the pieces carry
    no Collider2D). When testing through MCP inside ONE frame, call
    Physics.SyncTransforms() before each pick or it hits nothing.
  - Uses the LEGACY Input class (Input.mousePosition, Input.GetTouch) even though
    the project has com.unity.inputsystem installed. Works, but is inconsistent
    with the package set and will break if the project ever switches the Active
    Input Handling setting to "Input System Package (New)" only.
  - Per-frame cost: sub-steps x shape cells x obstacle boxes. A full 8x6 board
    is < 48 boxes, so a flick is a few thousand float compares - negligible, and
    bounded by maxSubStepsPerFrame.
  - Rounding is deliberately round-half-UP (RoundWhole / RoundAnchor), NOT
    Mathf.RoundToInt. Mathf rounds half to EVEN, so a piece released on exactly
    x.5 would snap left or right depending on the parity of the cell - which
    looks random to a player.
  - SnapNearWhole treats anything within 1e-4 of a whole cell AS that cell, in
    both IsFreeAnchorLegal and after each move (and on every snapshot box).
    Without it, float dust reads a flush contact as a sliver of overlap and the
    piece shivers against walls.
  - FIXED 2026-08-25 (was listed here as out of scope, wrongly):
    PieceSimple.SnapSubBlocksToOffsets laid sub-blocks out at
    (offset * board.CellSize) while the grid steps by CellPitch, overwriting the
    correct pitch spacing PieceShapeLayout had just applied - on the first
    TryPlace, which Start always runs. It was not cosmetic: the authored prefabs
    were already correct at pitch spacing, so this CORRUPTED them at runtime and
    drifted the collider centres TrySolveAnchorFromChildren depends on. Now uses
    CellPitch for SPACING and keeps CellSize for collider SIZE.
  - PieceDragHandlerSimple is a dead alternative drag path - zero scene and
    prefab references (verified by GUID). Do not confuse the two.

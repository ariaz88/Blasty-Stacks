PURPOSE
-------
The BRIDGE between the puzzle half and the combat half of the game. It detects
groups of matching connected pieces, clears them, and - crucially - fires the
static OnBlast event that causes a wave of player warriors to spawn.

This single event is the ONLY outbound dependency of the entire Puzzle layer.
Everything else in Puzzle knows nothing about combat, which is why the puzzle
module is so cleanly decoupled.

THE KEY EVENT
-------------
  public static System.Action<int> OnBlast;
      Raised with the number of groups cleared (always 1 in current code).
      PlayerWaveManager subscribes to it and spawns a wave of units in response.
      Being static means no wiring is needed between the two systems.

INSPECTOR FIELDS
----------------
  board                        (BoardGridXY) auto-found in Awake if unassigned
  minGroupSize                 (int, min 2, default 3) how many connected pieces
                               are needed before a match resolves
  preferMergeIfImmovablePresent (bool, default true) prefer sliding pieces
                               together over blasting them in place
  requireGeometricTouch        (bool, default true) LEAVE ON. Confirms two pieces
                               are REALLY touching before matching them, measured
                               on their actual bodies rather than on the cells
                               they have reserved. See GEOMETRIC TOUCH below.
  touchTolerance               (float 0-0.4, default 0.05) largest gap between two
                               bodies, in cells, still counted as touching. Keep
                               small: collision already parks a pushed piece
                               exactly flush, so this only absorbs float noise.
  minTouchOverlapCells         (float 0.05-1, default 0.2) how much of an edge two
                               bodies must share to count as touching. Stops a
                               pure diagonal corner-kiss from matching, exactly as
                               the old 4-neighbour rule did.
  killAnimTime                 (float, default 0.10) anticipation-beat duration,
                               measured at ~100 ms off the reference video
  enableDebug                  (bool) verbose logging

GEOMETRIC TOUCH  (ArePiecesTouching)
------------------------------------
  WHY IT EXISTS. BoardInputController's no-snap release mode
  (restExactlyWhereReleased) lets a piece rest between cells, and such a piece
  RESERVES every cell it overlaps so nothing can visually overlap it. A piece at
  x = 3.4 therefore holds cells 3 AND 4 while its body only spans 3.4 -> 4.4.
  The cell sweep in FindConnectedIdenticalGroup then expands one further cell out
  from that inflated reservation, so the match reach became
      body + up to 1 cell of inflation + 1 cell of neighbour search
  and pieces matched across a visible one- or two-cell gap. That was the bug.

  THE FIX. The cell sweep is now only a CANDIDATE filter - it deliberately
  over-reaches, which is exactly what you want from a cheap broad phase. Each
  candidate is then confirmed against real geometry.

  Each sub-block is a 1x1 box in continuous cell units at (anchor + offset), with
  the anchor read via BoardGridXY.WorldToContinuousAnchor. Two boxes touch when
  they overlap along one axis by >= minTouchOverlapCells and are separated along
  the other by <= touchTolerance.

  For GRID-ALIGNED pieces this reduces EXACTLY to the original 4-neighbour rule -
  orthogonal neighbours match, diagonals do not - so snap mode is unchanged and
  only the between-cells case is corrected. Verified against these cases:
      aligned side by side            -> match
      aligned, one cell gap           -> no match
      aligned, diagonal corner        -> no match
      A straddling at 3.4, B at 5     -> no match   (this was the reported bug)
      pushed flush by collision       -> match
      straddling Y only, touching X   -> match
      straddling X, 0.6 gap           -> no match

  CONSEQUENCE WORTH KNOWING. Because a straddling piece reserves the cell it
  partially covers, a neighbour can never sit flush against it ON THAT AXIS - so
  in no-snap mode you generally have to PUSH pieces together to match. Collision
  parks a pushed piece at exactly the whole-cell boundary, which is a true touch,
  so pushing always works. A piece can still be straddling on one axis and match
  on the other.

REUSED BUFFERS
--------------
  _footprint      (List<Vector2Int>)   reused to avoid per-call allocation
  _neighborCells  (HashSet<Vector2Int>) same

PUBLIC ENTRY POINTS
-------------------
  HasAnyStacksLeft() -> bool
      "Are there still any playable pieces on the board?" Re-finds the board if
      needed, then calls HasAnyActiveBlocksOnBoard.

  HasAnyActiveBlocksOnBoard()  [private]
      Calls FindObjectsOfType<PieceSimple>(false), then for each active piece
      asks board.TryWorldToCell to see whether it currently sits on the grid.
      Returns true on the first hit.
      !! PERFORMANCE: PlayerWaveManager.WaveLoop() calls HasAnyStacksLeft()
      !! inside a "while (...) yield return null" loop - i.e. ONCE PER FRAME
      !! while waiting. Each call allocates an array of every PieceSimple in the
      !! scene. This is the one genuine per-frame allocation in the project.
      !! A registration list on the board (pieces add/remove themselves in
      !! OnEnable/OnDisable) would remove it entirely.

  ResolveFrom(PieceSimple origin)
      The normal path, called after a piece is dropped.
      1. Flood-fills to find the connected group of matching pieces.
      2. Aborts if the group is smaller than minGroupSize.
      3. If preferMergeIfImmovablePresent, picks the nearest other group member
         and MERGES into it (an animated slide) instead of blasting.
      4. Otherwise clears the whole group.

  ResolveAll()
      Sweeps every piece in the scene, builds all groups with a visited-set so
      no piece is processed twice, and clears each qualifying group.

CORE SEARCH
-----------
  FindConnectedIdenticalGroup(seed) -> List<PieceSimple>
      Breadth-first search over the BOARD OCCUPANCY (not colliders). From each
      piece it builds the 4-adjacent cell ring around its footprint, reads the
      occupant id out of the grid, resolves it back to a piece via
      PieceSimple.GetById, and enqueues it when the shape and colour match.

  BuildFootprintNeighbors4(anchor, shape, outNeighbors)
      Collects every 4-neighbour cell of every cell in the footprint, then
      REMOVES the footprint's own cells so a piece never rediscovers itself.

  AreShapesMatchCompatible(a, b) -> bool     PUBLIC STATIC
      Shapes match if their ids are equal, OR they are one of two hard-coded
      compatible pairs:  B6 <-> B7,  and  B4 <-> B5.
      Made public static on 2026-08-25 so the tutorial layer
      (TutorialBoardHints) can ask "would these two blast?" without duplicating
      the rule and drifting from it. Behaviour is unchanged - it never used
      instance state.
      !! These shape ids are magic strings in code. A designer renaming a shape
      !! in the Inspector would silently break matching with no error.

  FindNearestWithWarriors(origin, group) -> PieceSimple
      Despite the name it does NOT check for warriors - it simply returns the
      nearest OTHER piece in the group by squared distance. Misleading name.

ACTIONS
-------
  ClearGroup(group)  [coroutine]
      Releases every piece's cells FIRST, so the player can keep moving other
      pieces while the clear animation plays. Then fires OnBlast(1), then plays
      the clear animation for each piece and destroys them.
      Two animation paths exist, selected by the DOTWEEN_ENABLED compile symbol
      (currently NOT defined, so the manual coroutine path is live).

  ScaleDownAndExplode(p)  [coroutine, non-DOTween path]
      Thin wrapper - delegates to CollapseThenBurst. Kept because ClearGroup
      calls it by name.

  CollapseThenBurst(p)  [coroutine]   -- rewritten 2026-08-25
      The shared clear beat for BOTH clear paths.
      1. Collapses the piece over killAnimTime (now 0.10s). It scales each
         per-cell CHILD independently with an ease-in, plus an 8% inward pull
         toward the footprint centre - not the root as one object. Splitting per
         cell is what reads as "it broke" instead of "it disappeared"; this is
         measured off Assets/Arts/Reference videos/Stack movement.mp4.
         Falls back to scaling the root if the piece has no renderer children.
      2. Calls FireBurst(), then destroys the piece immediately.
      The piece's sprite is sampled via PieceTintSampler at the START of the
      coroutine - while the GameObject still exists - so the shards match the
      block exactly. Sampling after the destroy would return nothing.
      Awake() also calls PieceTintSampler.WarmUp() once, which registers the
      canonical colour of every stack on the board with the flat 1X squares
      sampled FIRST, so the first clear of the session snaps onto a square's
      colour rather than one inferred from a bevelled 3X shape.
      Reuses the _collapseParts / _collapseOrigins scratch lists so a large
      clear allocates nothing.

  FireBurst(centre, footprintCells, colorId, tint)
      Calls ShardBurst.Play(centre, footprint, colorId, tint). Falls back to
      FractureObject.ExplodeAtPosition if no ShardBurst exists, so the VFX
      degrades rather than breaks.
      Both managers are cached in fields - the old code called
      FindObjectOfType<FractureObject>() once PER PIECE per clear.

  FootprintCentreWorld(p) / FootprintCells(p)
      Average of the piece's OccupiedCells centres, and the bounding box of
      those cells in cell units. Feed the burst position and emitter size.
      Both fall back sanely when OccupiedCells is empty.

  MergePieceInto(mover, target)  [coroutine]
      Computes a simple L-shaped path, steps the mover one cell per frame along
      it, then releases the target, fires OnBlast(1), and destroys both via
      FadeAndScaleDownThenDestroy.
      If no clear path exists it falls back to simply clearing both pieces.

  FadeAndScaleDownThenDestroy(p, t)  [coroutine, non-DOTween path]
      Now a thin wrapper over CollapseThenBurst.
      !! HISTORY WORTH KNOWING: until 2026-08-25 this only faded the piece to
      0.85 scale and destroyed it - it never touched the VFX at all. Since
      MergePieceInto is the path most real matches take (preferMergeIfImmovable-
      Present is on by default), most matches produced NO shatter effect
      whatsoever, no matter how FractureObject was tuned. If the effect ever
      "stops working" again, check that both paths still reach FireBurst.

  TryComputeStraightPath(from, to, shape, outPath) -> bool
      Greedy L path: all X movement first, then all Y. Every intermediate anchor
      must have a free footprint or the whole path fails. There is no
      pathfinding around obstacles.

  IsFootprintFreeAt(anchor, shape) -> bool
      Uses moverId 0, i.e. "treat the mover as nothing", so the mover's own
      current cells count as occupied during the check.

HOW IT CONNECTS
---------------
  - Reads BoardGridXY occupancy; resolves ids through PieceSimple.GetById.
  - Triggers ShardBurst for the shatter VFX (FractureObject is the fallback).
  - Fires OnBlast -> PlayerWaveManager spawns a warrior wave. THE core link
    between puzzle and combat.

PURPOSE
-------
The single facade for all Google AdMob traffic: banner, interstitial, and
rewarded ads. Gameplay and UI code never reference GoogleMobileAds types
directly - they call AdManager.Instance and receive plain C# callbacks. This
keeps the SDK dependency confined to one file and lets the rest of the project
compile with or without the plugin installed.

COMPILE GUARD - NOW ACTIVE (installed 2026-08-20)
-------------------------------------------------
  Every line that touches the SDK is wrapped in:

      #if GOOGLE_MOBILE_ADS ... #endif

  Without that define the class still compiles and behaves as a "no-ad mode"
  stub: loads are no-ops, IsRewardedAdReady is always false, and ShowRewardedAd
  immediately calls onAdUnavailable so callers never hang waiting for a
  callback that will not arrive.

  The SDK IS NOW INSTALLED and the define IS NOW SET, for Android, iOS AND
  Standalone (Standalone included so the editor can exercise the code path at
  all - the editor's active build target is StandaloneWindows64).

  Packages/manifest.json:
    com.google.ads.mobile                  git, v11.2.0
    com.google.external-dependency-manager git, v1.2.187

  NOTE both are GIT urls. EDM4U is normally pulled from Google's scoped
  registry (https://unityregistry-pa.googleapis.com), but that registry was
  unreachable from this machine and the resolve failed with "Package
  [com.google.external-dependency-manager@1.2.187] cannot be found". The git
  url is the working equivalent. If you ever restore the scoped registry,
  drop the git url for EDM4U at the same time - do not keep both.

INSPECTOR FIELDS
----------------
  Ad Units
    useTestIds (bool, default true)
        When true the serialized IDs are ignored and Google's official test
        units are used instead (TestAndroid / TestIos static readonly fields).
        Must be turned OFF before shipping.
    androidIds / iosIds (AdUnitIds)
        Serializable class with three string fields: banner, interstitial,
        rewarded. Production IDs go here.

  Lifecycle
    initializeOnAwake (bool, default true)   calls Initialize() from Awake
    preloadAfterInitialize (bool, default true)
        Loads one rewarded and one interstitial as soon as the SDK reports
        initialized, so the first Show has something ready.

  Retry
    retryDelaySeconds (float, min 0, default 5)
    maxLoadRetries (int, min 0, default 3)
        A failed load reschedules itself via a realtime coroutine, up to
        maxLoadRetries consecutive failures. The counter resets to 0 on any
        successful load.

  Banner
    showBannerAfterInitialize (bool, default false)
        Shows the banner as soon as the SDK reports initialized. Turn ON if you
        want the banner up everywhere; leave OFF and let AdBannerSlot request
        it per-scene instead.
    bannerSizeMode (BannerSizeMode, default AnchoredAdaptive)
        AnchoredAdaptive = full-device-width banner whose height the SDK picks
        for the device/orientation. This is Google's recommendation and it is
        what makes the banner fill the reserved strip on tall phones.
        Standard = the legacy fixed 320x50.
    bannerAnchor (BannerAnchor, default Bottom)  Bottom or Top of the screen.

PUBLIC STATE
------------
  Instance              static singleton handle
  IsInitialized         set once MobileAds.Initialize reports back
  IsRewardedAdReady     true while a loaded rewarded ad is held
  IsInterstitialReady   true while a loaded interstitial is held
  IsBannerVisible       true once a banner has loaded AND is on screen
  BannerHeightPixels    height of the loaded banner in SCREEN PIXELS, 0 when
                        none is loaded. Only meaningful after OnBannerLoaded.

EVENTS
------
  OnInitialized()                     SDK ready, preloads have been kicked off
  OnRewardedAvailabilityChanged(bool) true on successful load, false when the
                                      held rewarded ad is consumed or fails -
                                      intended for "Watch Ad" buttons that
                                      should grey out when no ad is available
  OnAdOpened() / OnAdClosed()         full-screen content opened/closed; useful
                                      for pausing gameplay or audio
  OnBannerLoaded(float heightPixels)  a banner loaded; arg is its height in
                                      screen pixels, for sizing the reserved UI
                                      strip (see AdBannerSlot)
  OnBannerFailed()                    banner failed and retries are exhausted

FLOW
----
  Awake()
      Standard project singleton guard + DontDestroyOnLoad, then Initialize()
      if initializeOnAwake.

  Initialize()
      No-ops if already initialized. Sets
      MobileAds.RaiseAdEventsOnUnityMainThread = true (so every SDK callback
      below is safe to touch Unity objects from) and calls MobileAds.Initialize.
      Without the define it logs a warning and goes straight to
      HandleInitialized so the no-ad path is still fully wired.

  HandleInitialized()
      Sets IsInitialized, fires OnInitialized, optionally preloads rewarded +
      interstitial and shows the banner.

  Rewarded
      LoadRewardedAd()  - skips if not initialized or one is already held.
      ShowRewardedAd(onRewardEarned, onAdUnavailable = null, onAdClosed = null)
          If nothing is ready: triggers a load and calls onAdUnavailable
          immediately. Otherwise stores the callbacks and shows the ad.
          onRewardEarned fires ONLY from the SDK's user-earned-reward callback.
      Full-screen closed  -> destroys the ad, fires onAdClosed + OnAdClosed,
                             then reloads the next one.
      Full-screen failed  -> destroys the ad, DROPS the pending reward, reloads.

  Interstitial
      Same shape. ShowInterstitial(onClosed) invokes onClosed even when no ad
      was available, so a "continue after the ad" flow never stalls.

  Banner
      ShowBanner() lazily constructs the BannerView using ResolveAdSize() +
      ResolveAdPosition(), hooks its events, loads it, and shows it. Calling it
      again on an existing view just re-shows it.
      HideBanner() hides without destroying and clears IsBannerVisible.
      DestroyBanner() tears the view down, clears IsBannerVisible and
      BannerHeightPixels, and is also called from OnDestroy.

      OnBannerAdLoaded  -> resets the retry counter, sets IsBannerVisible and
                           BannerHeightPixels from GetHeightInPixels(), fires
                           OnBannerLoaded(height).
      OnBannerAdLoadFailed -> clears IsBannerVisible; retries by REBUILDING the
                           view (ReloadBanner destroys then re-shows) because
                           the SDK cannot re-load a failed BannerView. After
                           maxLoadRetries it gives up and fires OnBannerFailed.

      ResolveAdSize()     AnchoredAdaptive ->
                          AdSize.GetCurrentOrientationAnchoredAdaptiveBanner
                          AdSizeWithWidth(AdSize.FullWidth); else AdSize.Banner.
      ResolveAdPosition() maps the BannerAnchor enum to AdPosition. The project
                          keeps its own enum so the serialized fields do not
                          depend on an SDK type - that is what lets the class
                          still compile with the define off.

  ScheduleRetry(ref retryCount, loader) / RetryAfterDelay(loader)
      WaitForSecondsRealtime so retries still tick while Time.timeScale is 0
      (pause menus, win/lose panels).

CALLING CONVENTION
------------------
  Guard, then show, then grant only in the callback:

      if (AdManager.Instance == null || !AdManager.Instance.IsRewardedAdReady)
      {
          SetButtonsInteractable(true);
          return;
      }

      AdManager.Instance.ShowRewardedAd(
          onRewardEarned:  () => GrantReward(3),
          onAdUnavailable: () => SetButtonsInteractable(true));

  NEVER grant the reward before ShowRewardedAd returns - the reward callback is
  asynchronous and may never fire.

HOW IT CONNECTS
---------------
  - AdBannerSlot (Assets/Scripts/Core/Ads/) is the banner consumer: it reserves
    the on-screen strip, calls ShowBanner/HideBanner with scene lifetime, and
    listens to OnBannerLoaded/OnBannerFailed to size that strip.

  The remaining intended consumers are:
    - RevivePanel  (watch an ad instead of spending a gem to revive)
    - WinPanel / LosePanel  (double-rewards, retry)
    - CurrencyManager  (the reward callback should route through AddGems /
      AddCoins so the grant persists via SaveSystem like every other currency
      change)

NOTES
-----
  - Follows the project's hand-rolled singleton pattern (public static Instance,
    guard-and-destroy in Awake, DontDestroyOnLoad) used by LevelManager,
    GameStartManager, and CurrencyManager. Note the portable /ads reference
    snippet writes AdManager.instance (lowercase); this project uses Instance.
  - OnDestroy clears Instance and destroys the banner.
  - No ScriptableObject config asset exists for the ad IDs yet - they are plain
    serialized fields on the component. If more placements are added, promoting
    AdUnitIds to an SO under Assets/Scripts/Data/ would match how the rest of
    the project stores design-time config.
  - The Editor shows a grey placeholder "test ad" panel; real creatives only
    appear on a device with internet.
  - THE BANNER IS A NATIVE OVERLAY, not a Unity UI element. The SDK draws it on
    top of the Unity view and it pushes nothing out of the way. Anything at the
    bottom of the Canvas will be COVERED unless a strip is reserved for it -
    that is the entire job of AdBannerSlot.
  - App IDs live in Assets/GoogleMobileAds/Resources/GoogleMobileAdsSettings
    .asset, NOT on this component (which only holds the per-placement ad unit
    ids). They are currently Google's TEST app ids:
        Android  ca-app-pub-3940256099942544~3347511713
        iOS      ca-app-pub-3940256099942544~1458002511
    An Android build with an empty/invalid app id CRASHES ON STARTUP, which is
    why they are filled in even for development.
  - SHIP CHECKLIST for this file: set useTestIds = false, fill androidIds /
    iosIds with the real unit ids, and replace the app ids in
    GoogleMobileAdsSettings with the real ones from the AdMob console.

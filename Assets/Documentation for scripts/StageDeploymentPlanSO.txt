PURPOSE
-------
Says WHICH hero types each match of each level awards, and how many of each.

LevelBattleRules.Deployments already says HOW MANY heroes a match is worth
(stage 4 is 1,1,2,4). It says nothing about WHICH types, and until now the types
were drawn at random from the deployed roster. PHASE 2 needs them authorable:
"match 1 gives one of type A, match 3 gives one A and one B" is a level-design
decision, not a dice roll.

OPTIONAL AND ADDITIVE - this is the important property:
  - A level WITH an entry here uses it verbatim.
  - A level WITHOUT one keeps the old behaviour exactly: counts from
    LevelBattleRules, types drawn at random.
Nothing breaks by leaving the asset empty, and levels can be converted one at a
time.

STRUCTURE
---------
  LevelPlan  { int level; List<MatchPlan> matches; List<IntervalOverride> deployIntervals; }
      level    1-based, the same number LevelBattleRules.ResolveLevel returns.
      matches  ONE ENTRY PER MATCH, in clear order. Element 0 is the FIRST match.
               May be left EMPTY: the level then keeps the random draw and the
               plan only carries interval overrides (Validate ignores it).
      deployIntervals  (added 2026-09-27) optional per-level card load times.

  IntervalOverride { int unitId; float seconds (>=0.1, default 6); }
      Replaces that type's UnitDefinitionSO.deployInterval in THIS level only.

  MatchPlan  { List<Entry> entries; }        empty = that match awards nothing

  Entry      { int unitId; int count; }
      unitId   UnitDefinitionSO.unitId of the type.
      count    how many of that type. The card deal shows ONE card per type with
               this number under it; the panel shows ONE cell reading "xN"; the
               spawn puts this many on the gates.

API
---
  HasPlanFor(level)            -> bool
  MatchCount(level)            -> int, 0 when unauthored
  EntriesFor(level, match)     -> IReadOnlyList<Entry> or NULL. match is 1-BASED,
                                  to line up with LevelBattleRules.HeroesForMatch.
                                  Null = fall back to the random draw.
  HeroCountFor(level, match)   -> total heroes that match awards
  TryGetDeployInterval(level, unitId, out seconds) -> bool
                                  true + seconds when that level overrides that
                                  type's load time; false = use the type's own.
  Validate()                   -> "" when consistent, otherwise a report. A level
                                  with ZERO matches authored is not reported.

HOW IT CONNECTS
---------------
  - PlayerWaveManager holds the reference (Inspector field `deploymentPlan`) and
    consults it in AwardHeroesForMatch. A null asset, an unauthored level or an
    unauthored match all fall through to the pre-PHASE-2 path.
  - The batch it produces flows to HeroCardRevealDirector (the card deal) and,
    counted per type, to HeroDeploymentSequencer, so authoring here changes what
    the player sees on the cards AND how many of each type deploy.
  - PlayerWaveManager.ResolveDeployInterval calls TryGetDeployInterval(RuleLevel,
    unitId) before falling back to UnitDefinitionSO.deployInterval.

NOTES / RISKS
-------------
  - !! WHEN A LEVEL IS AUTHORED, THE PLAN'S COUNTS WIN over LevelBattleRules. A
    match listing {A x2, B x1} awards three heroes whatever LevelBattleRules says.
    This is deliberate: the two tables never have to be hand-synced. Validate()
    REPORTS the disagreements as a design aid; it is not an error and does not
    block anything.
  - A unitId with no matching UnitDefinitionSO is skipped with a LogError rather
    than silently shrinking the wave - a typo'd id must be loud.
  - THE ASSET NOW EXISTS (2026-09-27): Assets/Scriptable Objects/Deployment/
    StageDeploymentPlan.asset, assigned on [PlayerWaveManager] in
    LevelTemplate.prefab (ASSET EDIT). All 20 Level_1_Stage_N scenes instance that
    prefab and none override deploymentPlan, so it reaches every stage.
    It is created EMPTY on purpose: an empty plan behaves exactly like no plan
    (random types, hero-default intervals). To change a load time for one level:
    Levels -> + -> level = N, leave Matches empty, Deploy Intervals -> + ->
    unitId + seconds.

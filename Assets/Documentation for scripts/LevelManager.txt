================================================================================
  LevelManager.cs
  Path : Assets/Scripts/Core/Progression/LevelManager.cs
  Type : MonoBehaviour - singleton, DontDestroyOnLoad
  Layer: Core / Progression
  Scene: MenuScene
================================================================================

PURPOSE
-------
Owns "which stage is the player on" for the whole game, and converts between two
ways of naming a stage:
  - GLOBAL stage:  a single running number, 1, 2, 3, ...
  - (LEVEL, STAGE-IN-LEVEL): e.g. Stage 1-16, with 20 stages per level.
It also optionally loads the scene that belongs to a stage.

SINGLETON
---------
  Instance          standard guard-and-destroy in Awake, then DontDestroyOnLoad.

INSPECTOR FIELDS
----------------
  stagesPerLevel  (int, default 20)  how many stages make up one "level"
  startingStage   (int, default 1)
  maxStage        (int, default 999) upper clamp
  stageSceneNames (string[])  optional scene name per stage; index = stage - 1.
                  Leave empty to manage scene loading yourself.

STATIC CONVENIENCE ACCESSORS
----------------------------
  CurrentStage             the global stage number (1 if no instance yet)
  CurrentLevelIndex        derived level  (1-based)
  CurrentStageIndexInLevel derived stage within that level (1-based)
  StagesPerLevel           20 if no instance yet
  These all fall back to sane defaults when Instance is null, so UI can read
  them safely during boot.

EVENTS
------
  OnStageChanged(int newGlobalStage)
  OnLevelStageChanged(int levelIndex, int stageInLevel, int globalStage)
      Raised immediately after OnStageChanged, giving the split form too.

METHODS
-------
  MarkLevelWon()          advances to CurrentStage + 1 and loads its scene
  RestartStage()          reloads the scene for the current stage
  SetStage(stage, loadScene = true)
      Clamps to 1..maxStage, persists via PersistCurrentStage() immediately,
      raises both events, then optionally loads the stage scene.

  PersistCurrentStage()  [static, added 2026-09-20]
      The single write path for "LM.CurrentStage". No-ops only when Instance is
      null (the normal case in Edit mode). Every previous inline
      PlayerPrefs.SetInt + PlayerPrefs.Save pair now routes through here, so
      every stage change is saved automatically and nothing in the UI has to ask
      for it. It used to also no-op while the SavePersistence debug gate was off;
      that gate was deleted on 2026-09-22.

  LoadSceneForStage(stage)  [private]
      Uses stageSceneNames[stage-1] when a non-empty name exists, otherwise
      reloads the CURRENT active scene by build index.

  GlobalToLevelStage(global, out level, out stageInLevel)
  LevelStageToGlobal(level, stageInLevel) -> int
  GetLevelIndex(global) -> int
  GetStageIndexInLevel(global) -> int
      The four conversion helpers. All are pure integer math using
      stagesPerLevel, and all guard against global < 1.

  HasReached(requiredLevel, requiredStageInLevel) -> bool
      "Is the player at or past Stage X-Y?" Used for unit unlock requirements.

  ResetProgressToStart()   [static]
      Resets to startingStage, rewrites PlayerPrefs (via PersistCurrentStage,
      so it too respects the debug gate) and re-fires both events.
      If the singleton does not exist yet it simply deletes the PlayerPrefs key
      so the next Awake starts fresh.

PERSISTENCE
-----------
  Uses its OWN PlayerPrefs key: "LM.CurrentStage". The constant was made PUBLIC
  on 2026-09-22 so SaveSystem.WipeAllProgress() can delete it by name - a wipe
  that forgets this key leaves an otherwise-fresh player standing on their old
  stage.

  Awake() always reads that key now, falling back to startingStage when it is
  absent (a fresh install, or right after a wipe). The 2026-09-20 debug gate
  that made it ignore the key was deleted on 2026-09-22.

  !! NOTE: this is the one place in the project that persists outside
  !! SaveSystem. The current stage therefore lives in a different key from the
  !! rest of the save file, and the two can get out of sync - for example if
  !! SaveSystem.ResetAll() runs without LevelManager.ResetProgressToStart().
  !! ResetAllIfRequested() in SaveSystem deliberately calls both to avoid this.

HOW IT CONNECTS
---------------
  - PlayerProgressionService.ProcessStageUnlocks() calls HasReached().
  - HomeManager / StageCard use the conversion helpers to build the stage map.
  - GameStartManager subscribes to OnLevelStageChanged.
  - WinPanel advances progress after a victory.

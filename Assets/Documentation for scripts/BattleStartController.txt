================================================================================
  BattleStartController.cs
  Path : Assets/Scripts/Combat/Spawning/BattleStartController.cs
  Type : MonoBehaviour
  Layer: Combat / Spawning   (drives a UI button, starts the combat phase)
  Scenes: Level_1_Stage_1 (on the "Battle" object under the Canvas).
          Verified 2026-08-31 by reading the saved .unity file - it is the ONLY
          scene in the project containing this component.
================================================================================

PURPOSE
-------
Drives the BATTLE button in the Feature Panel and owns the moment a stage
switches from its puzzle-only phase into combat.

New level flow: the stage opens with the board only - EnemySpawner sits idle
because its waitForBattleStart flag is ON, so nothing attacks and the player
can solve the puzzle for as long as they like. Pressing BATTLE charges the
player's global daily allowance through BattleEnergyService and, if that
succeeds, releases the spawner for the rest of the stage.

INSPECTOR FIELDS
----------------
  Refs
    battleButton         (Button) the BATTLE button. Left empty, Awake falls
                         back to a Button on this same GameObject.
    enemySpawner         (EnemySpawner) the stage's spawner. Left empty, Awake
                         finds it with FindObjectOfType(includeInactive: true).
    transition           (BattlePhaseTransition) camera pan + board hide. Left
                         empty, Awake finds it the same way. If the scene has
                         none, the battle starts immediately with no transition.

  Optional UI  (both are null-safe, leave empty and nothing breaks)
    energyCostText       (TMP_Text) the cost label under the BATTLE icon
    remainingBattlesText (TMP_Text) optional "left today" label, rendered as
                         "<remaining>/<dailyBattleLimit>"

  Daily Allowance
    dailyBattleLimit     (int, >=1, default 25) free battles per rolling 24h,
                         shared across every stage
    energyCostPerBattle  (int, >=0, default 25) PLACEHOLDER energy charged once
                         the free allowance is spent

  Behaviour
    hideButtonAfterBattleStarts  (bool, default ON) deactivates the button
                         GameObject once the battle begins

  Match Gate   (added 2026-08-31)
    requireMatchBeforeBattle (bool, default ON) the BATTLE button starts
                         NON-INTERACTABLE and only unlocks once the player has
                         actually cleared a match on the puzzle board. Stops a
                         stage being started with zero heroes recruited. OFF
                         restores the old behaviour - pressable from frame one.
    matchesRequiredToUnlock (int, >=1, default 1) how many matches to clear
                         before the button unlocks.
    lockedRoot           (GameObject) shown while the gate is SHUT - the Feature
                         Panel prefab's "Battle_Diactive". Switched off the
                         moment the first match lands. Null-safe.
    unlockedRoot         (GameObject) shown once the gate OPENS - the prefab's
                         "Battle_Active". Leave it switched OFF in the scene;
                         this script turns it on. battleButton should be the
                         Button that lives on THIS object. Null-safe.

  Testing
    doNotPersistAllowance (bool, default ON) TEST MODE. Pushed into
                         BattleEnergyService.SessionOnly in Awake. While ON the
                         daily allowance is memory-only, so every Play session
                         starts with a full 25 and nothing is written to the
                         save file. TURN OFF FOR RELEASE.

RUNTIME STATE
-------------
  BattleStarted   (bool, public get) true once this stage's battle phase has
                  been released. Latches - it is never reset by this component.
  MatchGateOpen   (bool, public get) true once enough matches have been cleared
                  for BATTLE to be pressable. ALWAYS TRUE when
                  requireMatchBeforeBattle is off, so a stage authored before
                  the gate existed behaves exactly as it always did.
  matchesCleared  (int, private) running count of OnBlast callbacks received.

EVENTS
------
  OnBattleStarted    fired the moment the battle phase begins
  OnBattleBlocked    fired when a press was refused - allowance spent, no
                     energy, OR the match gate still closed
  OnMatchGateOpened  fired when the gate opens, for a button-glow / tutorial cue

FLOW
----
  Awake()
      FIRST pushes doNotPersistAllowance into BattleEnergyService.SessionOnly,
      before anything can read the allowance, so the very first query already
      hits the in-memory store. Then resolves the two refs if they were left
      empty and logs an error for each one it still could not find. FINALLY seeds
      MatchGateOpen from requireMatchBeforeBattle and calls ApplyGateToButton -
      in AWAKE, before the first frame is drawn, so the button is never
      interactable for even one frame at stage open.

  OnEnable()
      Adds OnBattleButtonPressed to battleButton.onClick IN CODE, subscribes to
      BattleEnergyService.OnAllowanceChanged, subscribes OnBoardBlast to
      MatchResolver.OnBlast (only while the gate is still shut), and refreshes
      the labels.

  OnDisable()
      Removes all three subscriptions.

  OnBoardBlast(groups)   [private]
      Every cleared match on the puzzle board. Increments matchesCleared; once it
      reaches matchesRequiredToUnlock it sets MatchGateOpen, UNSUBSCRIBES from
      OnBlast (later matches are none of this component's business),
      calls ApplyGateToButton and fires OnMatchGateOpened.

  ApplyGateToButton()   [private]
      Swaps the two authored states - lockedRoot off / unlockedRoot on, or the
      reverse - so exactly one is ever visible; they occupy the same slot. ALSO
      writes battleButton.interactable, which is redundant while both roots are
      wired but is what keeps a scene using only a single always-visible button
      behaving correctly. Returns early if BattleStarted, so nothing can
      re-enable a button the battle has already consumed. Kept as one method so
      Awake and the unlock share a single code path and cannot drift apart.

  OnBattleButtonPressed()   [public]
      1. Returns immediately if BattleStarted (guards double-clicks).
      1b. Returns if the match gate is still shut, logging the
         matchesCleared/matchesRequiredToUnlock count and firing OnBattleBlocked.
         interactable=false already blocks the click; this guard exists because
         the method is public and could be called from a debug key.
      2. BattleEnergyService.Consume(dailyBattleLimit, energyCostPerBattle).
      3. On BlockedNoEnergy: logs how long until the window resets, fires
         OnBattleBlocked, refreshes UI, and returns WITHOUT starting anything.
         Nothing was spent.
      4. Otherwise calls StartBattle().

  StartBattle()   [public]
      Sets BattleStarted, optionally hides the button, hides lockedRoot, and
      FORCES MatchGateOpen true + unsubscribes from OnBlast - this is also the
      debug/revive entry point and bypasses the gate, so the flag is kept honest
      rather than left stale. Then fires OnBattleStarted,
      refreshes UI, then hands off to the transition:
          transition.Play(ReleaseSpawner)
      so the camera pans to the battlefield FIRST and ReleaseSpawner - which is
      what actually calls EnemySpawner.StartBattle() - only runs once it has
      settled. With no transition in the scene it calls ReleaseSpawner directly.
      This BYPASSES the allowance, so it is the right entry point for debug or
      revive flows that must not charge the player twice.

  ReleaseSpawner()   [private]
      The single place EnemySpawner.StartBattle() is called. Logs an error if
      there is no spawner.

  RefreshUI()
      Writes energyCostPerBattle into energyCostText and
      "remaining/limit" into remainingBattlesText. Both null-checked.

HOW IT CONNECTS
---------------
  - Calls EnemySpawner.StartBattle() - the single hand-off into the combat
    layer.
  - Calls BattleEnergyService.Consume / RemainingFree / TimeUntilReset and
    listens to its OnAllowanceChanged.
  - Subscribes to MatchResolver.OnBlast (Assets/Scripts/Puzzle/Match/
    MatchResolver.cs:11) for the match gate. That is a plain public static
    Action<int>, NOT a C# event and never cleared by MatchResolver, so the
    OnDisable unsubscribe is what stops a destroyed controller being invoked.
    PlayerWaveManager listens to the same delegate for hero waves.
  - Sits on the "Battle" GameObject under the Canvas in Level_1_Stage_1.

NOTES
-----
  - The onClick listener is added in code, so the button's OnClick list in the
    Inspector must stay EMPTY. Wiring it in both places would consume the
    allowance twice per press.
  - This component does NOT gate PlayerWaveManager. Hero waves still spawn and
    release on puzzle matches exactly as before; only the enemy side waits for
    BATTLE. That is a separate, still-open change.
  - The allowance is global, so pressing Replay / reloading the scene does not
    refund a battle. That is intentional: the cap is per 24h across the whole
    game, not per scene. NOTE this only holds ACROSS APP RESTARTS while
    doNotPersistAllowance is OFF; during the current test phase it is ON, so
    each Play session starts fresh.
  - THE MATCH GATE USES interactable, NOT SetActive. The button stays visible but
    greyed, so the player can see the goal. That means the Button's Disabled
    colour in its Transition block is what sells the locked state - if the button
    looks identical when locked, fix it THERE, not in this script.
  - The gate counts MATCHES, not pieces. MatchResolver fires OnBlast(1) once per
    cleared group, from two places - ClearGroup (MatchResolver.cs:330) and the
    move-and-kill path (MatchResolver.cs:546).
  - There is a TODO in OnBattleButtonPressed where the "not enough energy"
    popup or rewarded-ad offer should be hooked once the energy economy is
    written.

================================================================================
  HeroStatsPanel.cs
  Path : Assets/Scripts/UI/HUD/HeroStatsPanel.cs
  Type : MonoBehaviour
  Layer: UI / HUD   (battle-only HUD, reads HeroRoster, spends gems)
  Scenes: Canvas/Heros Stats panel  (gameplay stages)
================================================================================

PURPOSE
-------
The row of hero cells shown during a battle. One cell per hero TYPE that is on
the field when BATTLE is pressed, each showing "alive/total" - and, once every
hero of that type is dead, a gem price to buy the whole squad back into the
fight.

THE CELLS ARE BUILT AT RUNTIME. The scene holds ONE authored cell ("Hero 1")
which is used as a TEMPLATE and switched off at Awake. A stage that fields two
hero types gets two cells; one that fields four gets four. Nothing about the
panel is hard-coded to a particular hero.

A card's buy-back is good for ONE purchase PER LEVEL. Once used it never comes
back, even if that type is wiped out a second time (HeroStatCell.IsSpent). When
every card has been spent, BuyBacksExhausted goes true - and that is the gate
LastStandOffer waits on before it may show its own offer.

INSPECTOR FIELDS
----------------
  Cells
    cellContainer        (RectTransform) what the cells are parented to. PUT THE
                         HorizontalLayoutGroup HERE. Left empty = this GameObject.
    cellTemplate         (HeroStatCell) the authored "Hero 1" object. Left empty,
                         Awake takes the first HeroStatCell found in the
                         container's children, including inactive ones.
    forceCenterAlignment (bool, default ON) sets the container's layout group to
                         MiddleCenter at Awake, so a two-hero row sits centred
                         instead of hugging the left edge. Turn OFF to control
                         the alignment by hand.

  Buy Back Cost
    gemsPerHero          (int, >=0, default 50) FALLBACK price - this many gems
                         for EACH hero in the squad. Used only when the unit's
                         own UnitDefinitionSO.respawnGemCost is left at 0.

  Refs (left empty = found in the scene at Awake)
    waveManager          (PlayerWaveManager) does the actual respawning.
    gameStartManager     (GameStartManager) only used to reach unitsDatabase.

RUNTIME STATE
-------------
  cells          List<HeroStatCell> - the clones, in display order.
  unitsDatabase  UnitsDatabaseSO, cached from GameStartManager at Awake.
  built          latches true the first time the battle starts, so the cells are
                 never rebuilt mid-battle.

PUBLIC API (added 2026-09-06 for the LastStandOffer gate)
---------------------------------------------------------
  event Action OnBuyBackSpent
      Raised the moment a card's one-per-level buy-back is used up, AFTER the
      panel has finished repainting - so a handler reading BuyBacksExhausted
      from inside it gets the settled answer. LastStandOffer subscribes, because
      spending the LAST card is the one thing that can open its gate without the
      roster moving at all.

  bool BuyBacksExhausted
      True once every cell reports IsSpent. Requires `built`, so a panel that has
      not laid its cells out yet reads FALSE rather than vacuously true - its
      buy-backs are unspent, not absent. A battle that opened with no heroes
      builds zero cells and does report true; there is genuinely nothing to
      spend.

FLOW
----
  Awake()
      Resolves cellContainer / cellTemplate, DEACTIVATES the template, forces
      MiddleCenter on the layout group, resolves waveManager and
      gameStartManager, caches unitsDatabase. With no template it logs an error
      and disables itself (which also skips OnEnable).

  OnEnable()
      Subscribes to BattleStartController.OnAnyBattleStarted,
      HeroRoster.OnRosterChanged and CurrencyManager.OnCurrencyChanged. The
      currency one is here, not in HandleBattleStarted, so a panel switched off
      and on again mid-battle (built already true) keeps greying the price out.
      Then: if the battle is ALREADY running (BattleStartController
      .BattleIsRunning), builds via BuildAtEndOfFrame. That covers the normal
      case where this panel is listed in
      BattlePhaseTransition.showWhenBattleStarts and is therefore switched on
      AFTER the event has fired. Otherwise it just refreshes.

  BuildAtEndOfFrame()   [coroutine]
      WaitForEndOfFrame, then HandleBattleStarted. The wait matters because
      BattleIsRunning DEFAULTS TO TRUE for any stage with no
      BattleStartController - without it, such a stage would build on frame 0,
      before a single hero had run its Start() and registered, and the panel
      would come up empty.

  OnDisable()
      Drops all three subscriptions (including CurrencyManager's).

  HandleBattleStarted()
      Runs once (latched by `built`). HeroRoster.SnapshotStartingCounts()
      freezes the "/total" for every type standing on the field, then
      BuildCells(), then Refresh().

  BuildCells()
      Destroys any previous clones, asks HeroRoster.UnitIdsInBattle(), sorts
      them by UnitsDatabaseSO.IndexOf so the row reads the same way every run
      (not spawn order), then clones the template once per id and calls
      cell.Bind(unitId, def, squadSize, cost, HandleBuyBack).
      Empty roster = one warning, no cells. A unitId with no database entry also
      warns but still gets a cell (no portrait, cannot be bought back).

  ResolveGemCost(def, squadSize)
      def.respawnGemCost when it is > 0, otherwise gemsPerHero * squadSize.

  Refresh()
      For every cell: SetAlive(HeroRoster.AliveCount(id)) and
      SetAffordable(gems >= cell.GemCost). Called on every roster change and on
      every gem change.

  HandleBuyBack(cell)
      1. Bails if cell.IsSpent - the one-per-level rule, checked AHEAD of the gem
         charge. The button is already hidden and disabled by then, so this is
         belt-and-braces against a second click queued in the same frame, but it
         is also where the rule is authoritative.
      2. Bails if the type is not actually wiped out (AliveCount > 0).
      3. Bails if there is no waveManager.
      4. waveManager.CanSpawnReinforcements(unitId) is checked BEFORE the
         charge - a missing runtimePrefab must never eat the player's gems.
      5. CurrencyManager.TrySpendGems(cell.GemCost). Not enough -> log, refresh,
         return. No CurrencyManager in the scene -> warn and give it free.
      6. waveManager.SpawnReinforcements(unitId, cell.SquadSize).
      7. cell.MarkSpent() - BEFORE the Refresh, so SetAlive sees the flag and
         puts the count back where the price was instead of re-offering it.
      8. Refresh(), then OnBuyBackSpent (inside a try/catch, so one bad listener
         cannot break the panel).

HOW IT CONNECTS
---------------
  - HeroRoster            : the whole data source. Subscribes to OnRosterChanged.
  - BattleStartController : static OnAnyBattleStarted / BattleIsRunning.
  - PlayerWaveManager     : CanSpawnReinforcements + SpawnReinforcements.
  - CurrencyManager       : TrySpendGems + OnCurrencyChanged.
  - GameStartManager      : unitsDatabase (portraits, order, per-unit price).
  - HeroStatCell          : the cloned cell; this panel owns all its logic.
  - LastStandOffer        : READS BuyBacksExhausted and listens to
                            OnBuyBackSpent. It refuses to show while any card
                            here still holds an unused buy-back.

SCENE SETUP CHECKLIST
---------------------
  1. HorizontalLayoutGroup on the container (Child Alignment is forced to
     Middle Center by this script unless you turn forceCenterAlignment off).
  2. The authored "Hero 1" object needs a HeroStatCell with its own refs wired -
     see HeroStatCell.txt. Leave it ACTIVE in the scene; Awake switches it off.
  3. Add the panel to BattlePhaseTransition.showWhenBattleStarts if it should
     only appear during combat.

NOTES
-----
  - [2026-09-06] ONE BUY-BACK PER CARD PER LEVEL. Before this a card re-armed
    every time its type was wiped out again, so gems alone could keep a squad on
    the field for the whole stage. The latch is per-CELL (HeroStatCell.IsSpent),
    not a set of unit ids held here, so it cannot drift out of sync with the card
    it belongs to.
  - A hero type that is NEVER wiped out never spends its card. That is not a bug,
    but it has a visible consequence: with LastStandOffer.requireBuyBacksSpent on
    (its default), a battle where one type survives will never show the
    last-stand offer at all.
  - Heroes register with HeroRoster in their Start, i.e. the frame AFTER
    SpawnReinforcements instantiates them. The label therefore fills in one
    frame late; that is why HandleBuyBack does not try to set it itself.
  - The snapshot is taken once. A mid-battle revive (RevivePanel) spawns fresh
    waves against the OLD totals; HeroStatCell.SetAlive clamps to SquadSize so
    the label can never read "4/3".
  - Costs are per-battle only. Nothing here is written to SaveSystem - only the
    gem balance is, and CurrencyManager does that itself.

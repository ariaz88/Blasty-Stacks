CURRENT UPDATE - 2026-09-16  IT NO LONGER ASSERTS THE PRE-DECIDED RESULT
Three checks were removed because they verified the enforcement layer rather than
the game:
  * Check(battle.PlayerCP == count x 125)            - the hero normalisation that
                                                       erased the player's upgrades
  * Check(enemy CP sum == ReferenceEnemyCP(level))   - the enemy CP budget
  * Check(won == (matches >= FirstWinningMatch))     - THE forced outcome. It
                                                       demanded the result the
                                                       workbook had pre-decided.
CP is now whatever the units' own stats sum to, so there is no target to assert. It
is RECORDED instead: every row carries CP=player/enemy and the resulting R, next to
the actual Win/Loss. Accumulate those rows to build the ratio-to-win-rate table and
judge the model from that, rather than from a pass/fail on a scripted winner.

Still asserted: enemy count matches LevelBattleRules.TotalEnemies(level), and
FewestHitsBeforeDeath >= CharacterStats.SafetyBlowFloor (4). NOT eight - dying faster
than the base state is legitimate once one side has out-levelled the other.

OPEN WORK - this is still a single pass over stages 1-5, not the batch harness the
plan calls for. To measure win probability it needs to sweep R from ~0.7 to ~1.5 and
team sizes from 2v2 to 12v12, repeating each data point ~200x, and report a win rate
per cell. Pass criteria to aim for: R >= 1.20 wins >= 88%, R = 1.00 lands 40-60%,
R <= 0.85 wins <= 12%, and NO cell at 0% or 100% - randomness must survive.
It should also confirm the win rate MOVES when ATK alone is upgraded; if it does not,
the damage ceiling in CharacterStats is binding and base stats need more headroom.

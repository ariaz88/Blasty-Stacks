PURPOSE
-------
The floating health bar above a unit or gate. It fills a UI Image proportionally
to current health, keeps itself readable when the parent character flips to face
the other direction, forces itself above the character sprites while the battle
runs (and gives that priority back when the battle ends so win/lose panels can
cover it), and can stay hidden until the unit is actually IN the fight.
Since 2026-08-24 it also draws a DAMAGE TRAIL: a yellow chunk left behind at the
pre-hit health that drains away and fades, so a hit reads as a size rather than a
teleport. The trail Image is built at runtime by cloning the main bar, so units,
enemies and gates all get one with no prefab or scene re-authoring.

FIELDS
------
  healthBar           (Image) the filled bar; falls back to GetComponent<Image>

  Render Order
    forceOnTop        (bool, default true) push the owning world-space Canvas
                      above every character sprite. Without it the bar sits at
                      sortingOrder 1, tied with the units, so whichever unit
                      draws later covers the bars behind it.
    onTopSortingOrder (int, default 500) the order applied when forceOnTop is on.
    onTopSortingLayer (string, default "") optional sorting layer to move onto.
                      EMPTY = stay on the Canvas's layer and use the order alone.

  Battle Gate
    hideUntilBattleStarts (bool, default false)
                      ON  = stay hidden through the puzzle phase AND the camera
                            move, appearing only when the FIRST ENEMY is on
                            screen. Use on UNIT prefabs.
                      OFF = always visible. Keep off for GATE bars, which are
                            meant to be readable during the puzzle phase.

  Damage Trail  [2026-08-24]
    delayedBar        (Image) the second fill Image drawn BEHIND the main bar.
                      Holds the pre-hit health, then drains and fades. EMPTY +
                      autoCreateTrail = built at runtime; assign by hand only to
                      override the look.
    autoCreateTrail   (bool, default true) clone the main bar at Awake to make
                      the trail. This is why no prefab and no scene had to be
                      re-authored, and why GATE bars get one too.
    delayedColor      (Color, default 1.0/0.82/0.15) forced onto the trail in
                      Awake so no prefab can drift off-palette.
    trailHoldSeconds  (float, default 0.18) how long the chunk sits STILL at the
                      old value before draining. This pause is the readability.
    trailDrainPerSecond (float, default 0.9) drain speed as a fraction of the
                      FULL bar per second - so a 20% chip takes ~0.22s, and a
                      big hit visibly takes longer than a small one.
    trailFadeSeconds  (float, default 0.12) alpha fade once it has caught up.

  Runtime state
    ownerCanvas             (Canvas) the canvas shown/hidden. The COMPONENT is
                            disabled, not the GameObject, so nothing re-runs its
                            Awake when the bar comes back.
    hiddenOnGate            (bool) true while spawn code is holding this hero on
                            a castle gate - see SetHiddenOnGate.
    sortingCanvas           (Canvas) the canvas carrying the sorting order.
    authoredSortingOrder / authoredSortingLayer / capturedAuthoredSorting
                            what the prefab SHIPPED with, captured before
                            ApplyRenderOrder overwrites it.
    _baseLocalScaleX        (float) original absolute X scale, captured in Awake.
    trailFill               (float) what the trail is CURRENTLY showing. This is
                            the authority, NOT delayedBar.fillAmount, so the fade
                            cannot corrupt the drain maths.
    trailHoldTimer / trailFadeTimer / trailSeeded
                            hold-then-fade timers, and "the first
                            SetCurrentHealth was the spawn value, not a hit".

LIFECYCLE
---------
  Awake()
      Resolves the Image if unassigned, captures the authored sorting, applies
      the render order and the battle gate, subscribes to
      LevelGameManager.OnGameStateChanged, and - if the battle is NOT running -
      immediately restores the authored sorting (a bar spawned into an already
      finished battle never sees the event). Then FORCES the Image config:
          type        = Image.Type.Filled
          fillMethod  = FillMethod.Horizontal
          fillOrigin  = OriginHorizontal.Left
      Doing this in code means a designer cannot mis-configure the prefab.
      Finally stores the absolute base X scale.

  LateUpdate()
      Calls TickDamageTrail() then KeepUnmirrored(). Both used to be inline here.

  KeepUnmirrored()   [private, was the body of LateUpdate]
      Keeps the bar UNMIRRORED IN WORLD SPACE. Measures the world direction of
      the fill Image's own local +X, via
        healthBar.transform.localToWorldMatrix.MultiplyVector(Vector3.right).x
      and, only if that points along world -X, inverts this transform's
      localScale.x to cancel it. Early-outs when the value is ~0 (bar edge-on)
      or when the fill Image is not a descendant of this transform (it could
      not fix what it is measuring, and would flip-flop forever).
      Running in LateUpdate ensures it happens AFTER any facing logic has
      flipped the parent this frame.

      [2026-08-24] REWRITTEN. It used to read the sign of the PARENT's
      lossyScale.x and mirror itself whenever that was negative. That is a
      DOUBLE correction on the enemy prefabs: their root is authored at
      scale.x = -1, and the bar hierarchy already cancels that by hand - the
      Canvas ("PlayerProgressBarUI (1)"), "Bar (1)" and "BG (1)" each carry a
      180-degree Y rotation, and the two graphics also carry scale.x = -1
      (the un-mirrored "Bar"/"BG" originals are left in the prefab, disabled).
      Four inversions cancel to "upright", which is why the enemy bar looked
      correct in the Prefab/Scene view; the old LateUpdate then added a fifth
      at runtime, so enemy bars rendered MIRRORED in Play mode only - draining
      left->right against the player's right->left. Because the old code forced
      the Canvas sign to equal the root sign, the parity never changed with
      facing: it was mirrored whichever way the enemy turned.
      Two reasons the fix probes the world matrix rather than lossyScale:
      lossyScale cannot see a 180-degree rotation, and probing the FILL IMAGE
      (not this transform) accounts for the flips authored BELOW the Canvas.
      Player prefabs are clean (identity all the way down), so they now measure
      positive and are never written to at all.
      NOT YET VERIFIED IN PLAY MODE.

  OnDestroy()
      Unsubscribes from BOTH static events. Without this a hero destroyed before
      the first enemy appears keeps its subscription alive and throws later.

METHODS
-------
  SetCurrentHealth(currentHealth, maxHealth)
      Clamps currentHealth to >= 0 and maxHealth to >= 0.0001 to avoid a
      divide-by-zero, then sets fillAmount = current / max.

      [2026-08-24] It now also ARMS THE DAMAGE TRAIL, in three cases:
        - FIRST call ever (trailSeeded false): this is the spawn value, not a
          hit. Seed trailFill and stay hidden. EnemyStats.Start and
          PlayerStats.Start are the calls this catches; without it every unit
          would flash a chunk on frame one.
        - target >= trailFill (healed, or unchanged): snap trailFill up and hide.
          Otherwise a yellow chunk would be stranded ABOVE the real health.
        - target <  trailFill (damaged): trailFill still holds the PRE-HIT value,
          which IS the chunk, so just show it and re-arm trailHoldTimer. Re-arming
          on every hit makes a combo read as one continuous chunk, not a stutter.

  TickDamageTrail()   [private, called from LateUpdate]
      Hold -> drain -> fade, one stage per frame:
        holdTimer > 0            : count down, draw nothing new.
        trailFill > fillAmount   : MoveTowards at trailDrainPerSecond, write
                                   delayedBar.fillAmount; on arrival start the fade.
        fadeTimer > 0            : scale delayedColor.a down to 0.
        otherwise                : HideTrail().
      Uses SCALED Time.deltaTime on purpose - when the game is paused or a panel
      has frozen the level, the chunk should freeze with it rather than quietly
      finishing behind the pause menu.

  BuildTrail()   [private, called from Awake when delayedBar is empty]
      CLONES healthBar's GameObject into a sibling named "<name>_DamageTrail",
      strips its children and any component that is not Transform/CanvasRenderer/
      Image, and takes the main bar's sibling index - which pushes the main bar
      one slot LATER, and later siblings draw ON TOP in uGUI. That ordering is
      what makes the trail peek out only where health USED to be.
      Cloning rather than building from scratch is deliberate: it inherits the
      sprite, the RectTransform AND the enemy prefabs' hand-authored mirroring
      (180-degree Y rotation + scale.x = -1), so nothing has to re-derive that.
      HARD STOP: if the fill Image shares its GameObject with a HealthBar (the
      GetComponent<Image>() fallback), cloning would clone THIS script and the
      clone's Awake would clone again, forever. It logs a warning and bails.

  HideTrail()   [private]
      Disables the trail Image, restores delayedColor (undoing any fade alpha)
      and clears both timers.

  SetHiddenOnGate(hidden)   [public, added 2026-08-23]
      Hides the bar while its hero is STANDING ON THE CASTLE GATE, and gives it
      back once the hero has jumped into the field. Resolves ownerCanvas itself
      (ApplyBattleGate leaves it null when hideUntilBattleStarts is off).
      Un-hiding deliberately REFUSES to punch through the battle gate: if
      hideUntilBattleStarts is on and the enemies have not appeared, that gate
      still owns the bar and SetHiddenOnGate(false) leaves it hidden.
      Distinct from hideUntilBattleStarts on purpose - see NOTES.

  ApplyBattleGate()   [private]
      No-op unless hideUntilBattleStarts. Otherwise, if the enemies have NOT yet
      appeared, disables ownerCanvas and subscribes ShowForBattle to
      EnemySpawner.OnAnyFirstEnemySpawned. The cue is the FIRST ENEMY APPEARING,
      not the BATTLE press: pressing BATTLE only starts the camera move, so
      revealing there made the bars pop in mid-travel.

  ShowForBattle()   [private, event handler]
      Unsubscribes, then enables ownerCanvas - UNLESS hiddenOnGate is set, in
      which case the spawn pose still owns the bar.

  CaptureAuthoredSorting() / RestoreAuthoredSorting() / ApplyRenderOrder()
      Capture remembers the shipped order+layer once. ApplyRenderOrder writes
      onTopSortingOrder (and the layer if one is named), setting overrideSorting
      when the canvas is NESTED - a nested canvas ignores its own sorting
      otherwise. Restore puts the exact authored values back, and only undoes the
      layer move if we were the ones who made it.

  HandleGameStateChanged(state)   [private, event handler]
      Playing -> ApplyRenderOrder; anything else -> RestoreAuthoredSorting. A
      revive puts the level back into Playing, so this is a two-way trip.

HOW IT CONNECTS
---------------
  - PlayerStats, EnemyStats, PlayerGateStats and EnemyGateStats all call
    SetCurrentHealth after taking damage.
  - EnemySpawner.OnAnyFirstEnemySpawned / EnemiesHaveAppeared drive the battle
    gate.
  - LevelGameManager.OnGameStateChanged / IsBattleRunning drive the sorting
    hand-back.
  - PlayerWaveManager.SetHealthBarsHiddenOnGate calls SetHiddenOnGate for the
    mid-battle reinforcement spawn pose.

NOTES
-----
  - [2026-08-24] NOT VERIFIED IN PLAY MODE. The Unity Editor was closed for this
    session, so nothing below has been seen running - not the trail, not the
    mirroring fix. Both are compile-checked by reading only.
  - [2026-08-24] CALLER INCONSISTENCY that the trail makes visible:
    PlayerStats.Start passes maxHealth but PlayerStats.ApplyDamageToPlayer passes
    PlayerManager.statsBase.maxHP. If those two ever differ, the FIRST hit
    changes the denominator, so the fill jumps for a reason that is not damage
    and the trail shows a chunk of the wrong size (or none, if the ratio went
    up). EnemyStats uses maxHealth in both places and is fine.
  - The world-axis probe runs every LateUpdate for every unit on screen, but it
    is read-only unless the bar is actually mirrored - a matrix fetch and one
    float compare. Only enemy bars ever take the write branch.
  - [2026-08-24] The stale "fill from right -> left" comment next to
    fillOrigin = Left was corrected: the fill is anchored LEFT and empties from
    the RIGHT.
  - [2026-08-23] WHY SetHiddenOnGate EXISTS ALONGSIDE hideUntilBattleStarts.
    They hide the bar for the same visual reason ("not in the fight yet") but
    key off different things, and neither can replace the other:
      hideUntilBattleStarts is a ONE-SHOT gate resolved in Awake against
      "have the enemies appeared". It covers heroes gathering on the gates
      during the PUZZLE phase, because at that point no enemy exists.
      MID-BATTLE REINFORCEMENTS are bought long after the enemies are out, so
      ApplyBattleGate hits its early return and never hides anything - the bar
      would pop up on the castle gate during the spawn pose. SetHiddenOnGate is
      the explicit, battle-state-independent override for that window.
    The 500 sorting override must not outlive the battle: win, lose and revive
    panels all sit below it, so a bar left on top punches straight through them.

PURPOSE
-------
Runs the in-BATTLE roguelite loop: an XP bar fed by enemy deaths, a level-up that
pauses the game and offers three buff cards, and application of the chosen buff's
multiplier onto the matching players' UnitStatsRuntime.

PHASE GATE (important, and new)
  This layer only exists during the BATTLE phase. While the player is solving the
  puzzle there is no XP, no level bar and no cards - the army is still being
  assembled. It starts on BattleStartController.OnAnyBattleStarted.
  Consequence: the hero roster is FINAL before the first card is ever drawn.

TWO STAT LAYERS, kept strictly apart
  PERMANENT  PlayerStatsApplier computes baseStats x growth(saved upgrade level)
             into CurrentStats. Owned by the Units UI, written to the save file.
  PER-STAGE  this class multiplies CurrentStats on top. Never saved. Wiped by
             ResetForNewStage().
  A buff never touches the saved upgrade level, and an upgrade never touches a buff.

INSPECTOR FIELDS
----------------
  XP Progression
    xpSlider           (Slider)   driven NORMALIZED: min 0, max 1, set in Start
    levelCounterText   (TextMeshProUGUI)
    initialThreshold   (int, default 1)  LEGACY fallback, used only when no
                       config asset is assigned: threshold = initialThreshold +
                       level - 1
    xpIncreaseDuration (float, default 0.5)  seconds for the bar to cross its
                       full width. Logical XP is never delayed - but SINCE
                       2026-09-03 THE LEVEL-UP ITSELF WAITS FOR THIS FILL, so it
                       is no longer purely cosmetic. See "LEVEL-UP WAITS FOR THE
                       BAR" under NOTES.
    levelUpBarHoldSeconds (float, default 0.2)  ADDED 2026-09-03. Extra seconds
                       the bar is held VISIBLY FULL after the fill arrives and
                       before the card screen opens. Without it the bar reaches
                       100% and is wiped in the same breath, which reads as a
                       flicker rather than as "you filled it". 0 = fire the
                       moment the fill lands.

  Config
    config         (RogueliteConfigSO)  XP curve + card-draw tuning. Strongly
                   recommended; without it the legacy linear threshold is used
                   and the draw runs unweighted.
    unitsDatabase  (UnitsDatabaseSO)  used ONLY to look up a hero portrait for a
                   card, matched on UnitDefinitionSO.classType. Safe to leave
                   empty - cards then fall back to the buff icon.

  Skill Pool
    skillPool  (List<SkillData>)  ONE ASSET PER STAT, not per hero. The hero on
               each card is chosen at draw time by BuffDraw, so 5 assets across a
               4-hero roster already yields 20 distinct cards. Assets are NOT
               removed from this list any more - exhaustion is tracked per
               (hero, skill) inside BuffDraw.

  XP Bar Placement  [2026-09-03]
    THE BAR'S AUTHORED Y IS THROWN AWAY AT RUNTIME. PlaceXpBarUnderHud() runs from
    ShowXpBar() when the battle phase starts and rewrites the bar root's
    anchoredPosition, so moving the bar in the Canvas by hand does NOTHING - it
    snaps back the moment you press play. These three fields are the only way to
    move it.

    xpBarRoot            (GameObject)  the object actually MOVED - "Roquelite UI",
                         the parent of the slider, the XP badge and the count text,
                         so all three travel together. Empty = falls back to
                         xpSlider's parent.
    xpBarTopMargin       (float, default 200)  gap from the TOP of the screen to the
                         TOP EDGE of the slider, in canvas units. Smaller = higher.
                         The placement is MEASURED, not nudged: the code reads the
                         slider's real rendered bounds and corrects the difference,
                         so this lands identically regardless of how each of the 21
                         stage scenes authored the bar.
    xpBarHorizontalOffset (float, default 0)  left/right nudge. Pre-existing.
    xpBarVerticalOffset  (float, default 83.7)  ADDED 2026-09-03. Vertical nudge
                         applied AFTER the measured placement; POSITIVE = UP. This
                         is the field to drag when the bar just needs to sit higher
                         or lower - xpBarTopMargin keeps its "under the HUD" meaning
                         and this offsets from there.
                         The 83.7 default is measured, not guessed: at the 1125x2436
                         reference canvas the slider centred at Y 990.5 and the HUD
                         gem at Y 1074.2, so 83.7 lines the XP row up centre-to-centre
                         with the gem counter. That alignment holds on other aspect
                         ratios because the gem is anchored 147 below the top edge and
                         this placement is measured from the same top edge.
                         Being a NEW serialized field, it defaults to 83.7 in every
                         existing scene without any scene file being touched.

    Reg_Manager IS A PLAIN SCENE OBJECT IN EVERY STAGE SCENE, NOT A PREFAB
    INSTANCE. So any value typed into the Inspector fixes ONE scene only - there
    are 29 scenes under Assets/Scenes. Anything that should apply everywhere has to
    go in the field DEFAULT here in the script (as xpBarVerticalOffset does), or
    Reg_Manager needs turning into a prefab first. Still open.

  UI References
    levelUpOverlay, skillSelectPanel  (GameObject)
    cardSlots       (SkillCardUI[])  usually 3
    offensiveSlots, defensiveSlots  (Image[])  small icon rows showing every buff
                    picked so far, grouped by SkillData.category

EVENTS
------
  OnXpGained (Action<float>)  fires on every XP gain with its share of the
             current bar, e.g. 20f means "+20%". Intended for a floating popup.
  OnLevelUp  (Action<int>)    fires after each level-up with the new level.

RUNTIME STATE
-------------
  draw            (BuffDraw)  owns the roster, the per-(hero,skill) star counts
                  and the whole card-selection algorithm
  level           (int, 1-based)
  xp              (float)  LOGICAL xp toward the current threshold
  xpDisplay       (float)  what the slider currently shows; chases xp in Update
  isPaused        (bool)   a card screen is open
  running         (bool)   the battle phase has begun
  activePlayers   (List<PlayerStatsApplier>)
  activeEnemies   (List<EnemyManager>)
  skillMultiplier (Dictionary<(FighterType,SkillData), float>)  the multiplier
                  ONE buff currently contributes to one hero
  statMultiplier  (Dictionary<(FighterType,SkillEffectType), float>)  product of
                  every buff on one (hero, stat); used to catch up late joiners
  skillToSlot     (Dictionary<SkillData, Image>)  HUD icon row bookkeeping

FLOW
----
  Awake         builds the BuffDraw with the config asset.
  OnEnable/OnDisable  subscribe/unsubscribe BattleStartController.OnAnyBattleStarted.
  Start         hides the panels, resets state, normalizes the slider, and calls
                BeginBattlePhase() immediately IF BattleStartController.BattleIsRunning
                is already true. That flag DEFAULTS TO TRUE and is only cleared by
                a stage that actually has a BattleStartController - so a scene
                without one behaves exactly as it always did.

  BeginBattlePhase()
                snapshots the players on the field, derives the distinct
                FighterTypes from their CurrentStats.type, and hands that roster
                plus skillPool to draw.Configure(). A card can therefore never
                target a hero that is not in this fight.

  AddXP(float)  credits the XP IMMEDIATELY and in full, raises OnXpGained, then
                calls TryLevelUp. Update() catches the bar up separately, so kills
                landing faster than the fill animation can never be dropped or
                double-counted. (This was a real bug in the old coroutine version.)

  TryLevelUp()  deferred while a card screen is open. Otherwise:
                  xp -= Threshold      <- THE OVERFLOW CARRIES, never reset to 0
                  level++
                then opens the card screen. Re-checked after every pick, so one
                elite kill can cascade several levels.

  OpenSkillSelection()
                asks draw.Draw(cardSlots.Length). If it returns nothing (all
                buffs maxed) the screen is SKIPPED and the game never pauses.
                Otherwise pauses via GameplayPause.SetPaused(true) and fills the
                slots with Init(offer, portrait, callback).

  OnOfferChosen(BuffOffer)
                draw.Commit -> ApplyOffer -> AddSkillToList -> close -> TryLevelUp.

  ApplyToHero() applies only the RATIO new/old of this buff's multiplier, so
                taking the same card again moves the stat from its old total to
                the new one instead of compounding. Records both the per-skill and
                the per-stat product.

  RegisterPlayer()
                adds the player AND immediately applies every buff already taken
                for its hero type (ApplyAccumulatedTo), so a unit that reaches the
                field late is never under-buffed.

  ResetForNewStage()
                clears level, xp, both multiplier tables and the HUD icon rows,
                then reconfigures the draw. Does NOT touch the saved upgrade level.

HOW IT CONNECTS
---------------
  EnemyManager.Update()  -> NotifyEnemyKilled(this) on death, guarded by xpGiven.
                            Grants enemy.XpValue. THIS IS THE ONLY XP SOURCE.
  PlayerWaveManager      -> RegisterPlayer for each spawned unit.
  BattleStartController  -> OnAnyBattleStarted (static) starts the whole layer.
  BuffDraw               -> decides which (hero, stat) cards appear.
  SkillCardUI            -> renders one BuffOffer.
  GameplayPause          -> the single pause authority (also sets Time.timeScale).
  UnitStatsRuntime.ApplyMultipliers(atk, def, hp, move, atkSpd, range)
                         -> where every buff ultimately lands.
  PlayerStats            -> live health is scaled alongside a maxHP buff, or the
                            buff would be invisible.

NOTES
-----
  - LEVEL-UP WAITS FOR THE BAR  [FIXED 2026-09-03]
    THE BUG: TryLevelUp ran in the SAME FRAME as the kill and set xpDisplay = 0
    while the fill animation was still travelling. At roguelite level 1 the
    threshold is 2 kills, so each enemy is ~50%: the first kill filled the bar to
    50%, and the second wiped it from 50% straight to 0 and opened the card
    screen. The bar NEVER rendered anything between 50% and 100%. What the player
    saw was a stuck half-full bar, cards appearing out of nowhere, and then the
    ~2% overflow crawling up from zero seconds later. Worst on the FIRST level
    because the threshold is smallest there, so each kill is the largest share of
    the bar.

    THE FIX: the level-up is gated on the DISPLAY, not the number.
      * AddXP still credits logical XP immediately and in full - nothing about
        the accounting changed, so no kill can be lost or double-counted by the
        wait.
      * TryLevelUp, on finding xp >= Threshold, checks xpDisplay. If the fill has
        not arrived (or has not yet been held for levelUpBarHoldSeconds) it sets
        pendingLevelUp and returns WITHOUT touching xp or level.
      * Update() retries every frame while pendingLevelUp, advancing barFullTimer
        only once xpDisplay is actually at full.
      * ORDER INSIDE Update MATTERS: xpSlider.value is assigned BEFORE TryLevelUp
        is called, because TryLevelUp may zero xpDisplay and the player has to see
        the full bar for that frame.
    New private state: pendingLevelUp, barFullTimer, const BarFullEpsilon (0.001).
    Both are cleared in ResetProgressionState AND in ShowXpBar, so a restarted or
    revived battle cannot inherit a stale pending level-up.
    A CASCADE still works: after the card closes, xpDisplay is 0 and the overflow
    has to fill the bar again before the next level fires - slower than before,
    but it is now visible instead of instant.
    xpIncreaseDuration = 0 bypasses the whole gate and fires immediately.
    NOT PLAY-TESTED.
  - Buffable stats are FIVE: AttackDamage, Defense, Health, AttackSpeed,
    MoveSpeed. attackRange is deliberately excluded from the pool for now; the
    multiplier plumbing for it still exists in UnitStatsRuntime.
  - The old numbered dead siblings AddXP1() and AddSkillToList1() are GONE, as are
    the AnimateXpBar / DelayedLevelUp coroutines they raced with.
  - The old code set Time.timeScale directly while combat honoured
    GameplayPause.IsPaused - two competing pause systems. Now only GameplayPause.
  - Every serialized field name from the previous version is preserved, so the
    21 stage scenes still deserialize. config and unitsDatabase are new and will
    be null in scenes authored before this change: the legacy threshold is used
    and cards simply have no portrait. Assign them per stage.

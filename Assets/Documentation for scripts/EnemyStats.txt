CURRENT UPDATE - 2026-09-16 (supersedes everything below about damage adjustment)
ApplyDamageToEnemy NO LONGER ADJUSTS DAMAGE AT ALL. CPBattleController.AdjustIncomingDamage is gone with the rest of the enforcement layer, so the blow lands exactly as the attacker's stats produced it. The order is now:
    damage = ClampIncomingBlow(damage, attacker)     loose safety guard only (maxHP/4)
    CPBattleController.ReportBlow(this, damage)      OBSERVATION ONLY, returns void
    SetResolvedHealth(...)
The scripted tutorial exchange that used to set an enemy's damage outright in levels 1-3 is gone; every stage runs real combat. `attacker` is still passed, now only so CharacterStats.ReportDeath can print the per-attacker hit breakdown.

--------------------------------------------------------------------------------
SUPERSEDED - 2026-09-10 (kept for history)
ApplyDamageToEnemy now passes real incoming hit damage through CPBattleController.AdjustIncomingDamage. SetResolvedHealth is called only from the incoming damage method; no timer or team-budget controller calls it. Missing health bars are safe. Defeat still follows actual HP reaching zero and EnemyManager processes normal death/XP.

================================================================================
  EnemyStats.cs
  Path : Assets/Scripts/Combat/Enemy/EnemyStats.cs
  Type : MonoBehaviour, extends CharacterStats
  Layer: Combat / Enemy
  Scenes: all 7 gameplay stages
================================================================================

PURPOSE
-------
An enemy's live health, plus the "approach slots" that tell attacking players
where to stand. Extends CharacterStats for the HP fields.

FIELDS
------
  enemyManager      cached in Awake
  healthBar         (HealthBar) floating bar
  enemyIsdead       (bool) set when HP reaches zero
  EnemyOffsetLeft   (Transform) a stand-here point on the enemy's left
  EnemyOffsetRight  (Transform) the same on its right

LIFECYCLE
---------
  Awake()  caches the EnemyManager
  Start()  initialises the health bar if one is assigned (null-checked)

METHODS
-------
  GetOffsetFacingPlayer(Vector2 playerPos) -> Transform
      Returns whichever side offset is NEARER the given player position, using
      squared distance (no sqrt). Falls back to whichever single offset exists,
      and finally to the enemy's own transform if neither is set.
      This is what makes attackers surround an enemy from the correct side
      instead of all piling onto one point.

  ApplyDamageToEnemy(float damageAmount, PlayerManager attacker = null)
      FIRST calls enemyManager.NotifyAttackedBy(attacker) - added 2026-09-21.
      Being hit is the ONLY thing that lets an enemy turn round for a hero
      standing behind it, and even then it faces and fights IN PLACE rather
      than walking back. See EnemyManager's no-backtracking section.
      Then clamps the blow, reports it to CPBattleController (observation only)
      and applies it. HP cannot fall below zero and negative damage cannot
      heal. Refreshes the bar. Sets enemyIsdead at zero HP.

HOW IT CONNECTS
---------------
  - PlayerDamageCollider calls ApplyDamageToEnemy, and is therefore what feeds
    the enemy's retaliation memory.
  - EnemyManager polls enemyIsdead to run the death sequence and award XP.
  - TargetDetectionForPlayer uses GetOffsetFacingPlayer to pick an approach slot.

NOTES
-----
  - healthBar is null-checked in Start but NOT in ApplyDamageToEnemy, so an
    enemy prefab without a bar throws on its first hit.
  - Unlike PlayerStats, the bar is refreshed against maxHealth consistently
    here, so it does not suffer the denominator mismatch PlayerStats has.

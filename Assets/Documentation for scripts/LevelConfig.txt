CURRENT UPDATE - 2026-09-10 (supersedes conflicting older notes below)
Stages 1-5 runtime overrides now live in LevelBattleRules, CPBattleController and EnemySpawner. No timer-driven CP fields are used. Authored enemy types/first-wave area are retained, but authored counts and later waves are replaced at runtime for these stages only. Stage 6+ reads the asset normally.

================================================================================
  LevelConfig.cs
  Path : Assets/Scripts/Combat/Spawning/LevelConfig.cs
  Type : ScriptableObject   (menu: "TD/Level Config")
         + 2 supporting enums + 2 [Serializable] plain classes in the same file
  Layer: Combat / Spawning
  Scenes: all 7 gameplay stages
================================================================================

PURPOSE
-------
The complete design-time definition of one stage's ENEMY waves: how many waves,
what is in each, where they spawn, and in what formation. One asset per stage,
consumed entirely by EnemySpawner.

TOP-LEVEL FIELDS
-----------------
  levelNumber          (int, default 1)  fallback CP/progression level used only
                       if LevelManager is not present in the scene
  startDelay           (float, default 2)  seconds before the first wave
  targetStageDuration  (float, default 90)  intended pacing target - NOT enforced
                       anywhere in code, purely documentation for the designer
  waves                (List<Wave>)  the sequential wave list

TYPES DEFINED IN THIS FILE
----------------------------
  enum SpawnFormation { AllTogetherGrid, TwoRows }
      AllTogetherGrid - every entry's units interleaved into one grid layout
      TwoRows         - a front row and a back row, optionally staggered in time

  enum FrontRowAnchor { MinY, MaxY }
      Whether the "front" row (the one that spawns first, closer to the player)
      sits at the low or high end of the spawn rectangle's Y range.

  enum RowIndex { FrontRow = 0, BackRow = 1 }
      Which row a WaveEntry belongs to (only meaningful in TwoRows formation).

  class Wave  [Serializable]
      name               (string, default "Wave")  for readability in the
                         Inspector list, not used by code
      delayBeforeWave    (float, default 5)  pause before this wave starts
      spawnOnTimerOnly   (bool, default FALSE)  added 2026-09-21.
          ON  = this wave arrives on a FIXED timer, exactly delayBeforeWave
                seconds after the previous wave SPAWNED, whether or not the
                previous wave is dead. Waves can overlap. Used where the stage
                wants a predictable beat - stage 6 runs 11s then 13s.
          OFF = the original behaviour: wait for the field to be cleared,
                bounded by EnemySpawner.MaxSecondsBetweenWaves (8s).
          It defaults OFF deliberately. Making the timed path the shared
          default would have sent wave 2 of every other stage after its
          authored ~1.5s instead of after a clear - a large, unrequested
          difficulty jump across stages 4, 5 and 7-20.
      formation          (SpawnFormation, default AllTogetherGrid)
      spawnMin / spawnMax (Vector2)  the world-space rectangle enemies spawn
                         inside (defaults (1,2) to (10,4))
      gridColumns        (int, default 0 = auto ceil(sqrt(total)))
      minSlotSpacing     (Vector2, default (0.4, 0.4))  minimum gap between
                         auto-placed slots
      frontAnchor        (FrontRowAnchor, default MinY)
      rowYOffset         (float, default 0 = auto from area height)
      secondRowDelay     (float, default 0.2)  gap between spawning the two rows
      entries            (List<WaveEntry>)  the archetypes and counts in this wave
      concurrencyCap     (int, default 0 = unlimited)  declared but UNUSED by
                         EnemySpawner - a planned "drip spawn" cap that was never
                         wired up

  class WaveEntry  [Serializable]
      enemyPrefab   (GameObject)  must carry an EnemyManager component
      statsBase     (UnitStatsSO)  which base stat sheet this archetype uses
      count         (int, min 1, default 3)
      row           (RowIndex, default FrontRow)  only read in TwoRows formation
      unitLevel     (int, min 1, default 1)  the PROGRESSION level for this
                    entry (feeds ProgressionConfigSO growth, distinct from the
                    stage-based CP weighting)

HOW IT CONNECTS
---------------
  - EnemySpawner reads levelNumber, startDelay and waves to drive the whole
    stage's enemy timeline.
  - WaveEntry.statsBase and enemyPrefab are handed to EnemyManager.Initialize.
  - Assets: "Assets/Scriptable Objects/Spawner/Spawner1.asset",
    "Spawner2.asset".

NOTES
-----
  - unitLevel here (per-entry progression level) is INDEPENDENT of stageLevel
    (the CP-weighting lens EnemySpawner computes from LevelManager.CurrentStage
    at runtime and passes separately into EnemyManager.Initialize). A designer
    could set a low unitLevel on a strong late-stage entry and get a
    combination that does not scale the way expected - the two numbers are easy
    to confuse.
  - concurrencyCap is authored in the Inspector but has no effect - EnemySpawner
    never reads it.
